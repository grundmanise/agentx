## Text output

Every command prints aligned text for you to read.

- Tables pad their columns.
- A row that reports a state starts with a glyph: `✓` ok, `!` warning, `✗` failure, `•` information.
- A command that changes something confirms it on one line, such as `agentx config set label "work laptop"`:

```text
✓ label is now work laptop
```

agentx did not write some of the text it prints, such as skill names and descriptions, MCP server command lines and messages from git servers. In that text, agentx replaces tabs, newlines and other control characters with spaces. This keeps each item on one row, and that text cannot control your terminal.

If a path holds a control character, agentx prints it in double quotes with escapes, as `git status` does. You can still copy the path:

```text
    nasty  directory  user  "/home/me/.claude/skills/na\033[31msty"
```

## Colour

Text output is coloured when it goes to a terminal. Each colour has one meaning:

| Colour | Meaning |
|---|---|
| Green | OK, enabled |
| Yellow | Warning, hint, disabled |
| Red | Failure, error |
| Blue | Information |
| Cyan | A key, a command or flag name, or a count |
| Magenta | A tag, such as a plugin name |
| Dim | Secondary detail |

Output that goes to a file or another program has no colour, so a script reads plain text. To choose yourself, use the global `--color` flag:

```sh
agentx --color on doctor | less -R
agentx --color off scan
```

Set the `NO_COLOR` environment variable to any value, or set `TERM` to `dumb`, to turn colour off. `--color on` turns it back on.

## Logs

agentx writes logs to stderr. A line that starts with `warning:` reports a problem that did not stop the command. Add `--verbose` to also see `debug:` lines, such as which agentx home and library the command used.

Some warnings put what to do on a second line, indented under the warning.

## Errors

A failed command prints `error: ...` on stderr. If there is a fix, a `hint: ...` line follows. With `--json`, the error is an `error` event on stdout.

## Exit codes

| Exit code | Meaning |
|---|---|
| 0 | Success. |
| 1 | The command line is wrong: an unknown command, a bad flag or value, flags that cannot go together, or a missing argument. Run `agentx help`. |
| 2 | Git is missing or older than 2.40. Install or upgrade git. |
| 3 | agentx cannot reach a source or the [account remote](/cli/source#add-your-account-remote), or the remote denied access: authentication failed, or it did not let this machine push or [delete a branch](/cli/fork#remove-a-skill-of-your-own). Check your credentials and network. |
| 4 | A merge is pending. Either a pending merge blocks the command, or `skill update` found a conflict and left a merge for you to resolve. See [When your edits conflict](/cli/skill#when-your-edits-conflict) and, for one of your own skills, [Resolve a conflict](/cli/fork#resolve-a-conflict). |
| 5 | Something you named does not exist: a skill, a source, a ref or directory in a source, a configuration or a file. |
| 6 | agentx refused because something is in the way or changed meanwhile. Examples: a name is already taken, a server rule such as a hook declined a push (see [Publish a skill](/cli/skill#publish-a-skill)), or a source changed a skill you publish to it (see [Publish edits to a shared source](/cli/skill#publish-edits-to-a-shared-source)). |
| 7 | Another agentx command is running. Retry when it finishes. A command waits a few seconds for a scan, such as the desktop app reading your skills, before it stops with this code. |
| 8 | git cannot use the account repo, `account.git` in agentx home. Run `agentx doctor`. |
| 9 | You stopped the run with Ctrl-C, or something sent it a `SIGTERM`. See [Stop a run](#stop-a-run). |
| 10 | An internal error, such as a file agentx cannot read or write. Read the message and hint. If they name no cause, report it as a bug. |

## Stop a run

To stop a run, press Ctrl-C or send `SIGTERM`. agentx stops the git command it is running, prints an error with a hint, and exits `9`:

```text
error: interrupted
hint: run the command again; 'agentx doctor' names anything the stop left behind
```

A change that had already started is finished before the run stops, and one that had not started leaves nothing behind.

Ctrl-C in a terminal also reaches the git command agentx is running, so a change can stop part way. The next agentx command finishes or rolls back that change, and `agentx doctor` shows if one is waiting. Run the command again when you are ready.

To kill a run that does not stop, press Ctrl-C a second time. The next agentx command cleans up in the same way.

If the run had already done everything you asked, it exits `0` and reports what it did.

## Environment variables

| Variable | Default | Use |
|---|---|---|
| `AGENTX_HOME` | `~/.agentx` | Where agentx keeps its own state. |
| `AGENTX_LIBRARY` | `~/.agents/skills` | The library of skills agentx manages. |

Set either variable to move that directory. agentx needs `HOME`, and reads `XDG_CONFIG_HOME` (default `~/.config`) to find your agent clients.

## JSON output

Add `--json` to any command to print one JSON object per line. The agentx desktop app reads this output. From a terminal, the text output is all you need.
