---
title: "agentx snapshot"
description: "Save a snapshot of one machine, with its settings, to a file in your library or to your account repo, and apply it to another."
---

`agentx snapshot save` writes a snapshot of this machine to a file in your library, or to your account repo: your settings, your agent configurations, the skills in your library with where each one is placed, and the MCP servers and plugins agentx found. `agentx snapshot apply` applies a snapshot: it restores the settings, installs the skills, and places each one where the snapshot says.

A snapshot is the whole state of one machine, so it always holds that machine's settings. A snapshot holds no skill content. For each skill it records where the skill comes from, which version you had and which configurations you placed it in. Applying it installs the content again from each skill's source, or from your [account repo](/account-repo) for your account skills.

## Move to a new machine

1. On the old machine, run `agentx snapshot save`. It writes `snapshot.json` to your library, `~/.agents/skills` by default.
2. Copy the file to the new machine, for example to `~/snapshot.json`.
3. On the new machine, run `agentx snapshot apply ~/snapshot.json`, and answer `y`.

Applying it installs each skill at the version you had and places it in the same configurations. Use the same steps to restore a machine from its own snapshot, for example after you removed your skills.

## Save a snapshot

```sh
agentx snapshot save
```

```text
✓ saved the snapshot of the settings and 12 skills to /home/me/.agents/skills/snapshot.json
```

Save writes the file to your [library](https://github.com/grundmanise/agentx/blob/main/GLOSSARY.md), next to your skills, where every agent that reads the library leaves it alone. Without a name, the file is `snapshot.json`. Give a name to keep more than one snapshot:

```sh
agentx snapshot save work-laptop
```

```text
✓ saved the snapshot of the settings and 12 skills to /home/me/.agents/skills/work-laptop.json
```

The name is a file name without an extension. Save adds `.json`. A name with an extension, a slash, or a leading dot stops save with exit code 1. `agentx snapshot save --help` prints the path of the file save writes.

The file holds:

| Part | What it is |
|---|---|
| `settings` | Your [settings](/cli/config) as `settings.json` holds them, for example the label, your sources and their pins, disabled configurations and copy modes. |
| `configurations` | Each agent configuration on this machine, by its id, such as `claude-code`, and whether it is enabled. |
| `skills` | One entry for each skill in your library: its name, whether agentx manages it, where it is published (its source, or your account repo for your account skills), where a skill you forked came from (its upstream), the version it is at, and the configurations it is placed in. |
| `mcp_servers` | Each MCP server, with the tools it exposed, the configurations that declare it, and the command, arguments or URL each one declares, as written there. Only the names of environment variables and headers are kept, never their values. |
| `plugins` | Each plugin, with its marketplace, version and configuration. |
| `machine` | The id and label of the machine you saved it on. |

A snapshot leaves out what only describes this machine: where agentx found each configuration, skill and plugin on disk, whether a skill is modified or has drifted, and the ids `agentx scan` uses. Two saves of an unchanged machine are the same file, byte for byte, so you can compare them.

A snapshot keeps each MCP server's command, arguments and URL as your configuration writes them, and these can hold a token. Treat the file like a secret, and do not commit it to a public repository. A new file is readable by you alone. When you overwrite a file with `--force`, it keeps its old permissions.

If the file is already there, save stops with exit code 6. Pass `--force` to replace it:

```sh
agentx snapshot save --force
```

If a directory of that name is in the library, save stops with exit code 6, also with `--force`. If you have no library yet, save creates it.

If a skill in your library has a name agentx cannot store as a branch, save leaves it out of the snapshot and prints a warning that names it.

If agentx cannot read your library, or part of it, save prints a warning for each problem, as `agentx skill list` does, and the snapshot leaves out what it could not read. Fix the problem the warning names and save again.

## Apply a snapshot

Apply takes the path of a snapshot file:

```sh
agentx snapshot apply ~/snapshot.json
```

```text
Replace the settings in /home/me/.agentx/settings.json with those of my-laptop from /home/me/snapshot.json, and install, update and place its 4 skills? [y/N] y
✓ Snapshot applied

Skills added (1)
  pdf   Claude Code, Codex

Skills updated (1)
  xlsx  Claude Code

Skills skipped (1)
  notes  was created by hand, so there is no source to install it from

Sources added (2)
  https://github.com/example/skills
  https://github.com/example/tools

Agents enabled
  Claude Code, Codex

1 skill already up to date
```

Apply asks once. Answer `y` or `yes` to apply the whole snapshot. Any other answer changes nothing, so answering no is how you check a snapshot first. Apply then does this:

| The snapshot has | What apply does |
|---|---|
| Settings | Replaces your settings with them, but keeps this machine's URL of your account repo, see below. agentx checks write access to each source again on this machine. |
| Sources in the settings | Adds each source this machine has not added yet, your account repo included, at the pin the settings hold. Apply prints one line per source it adds. |
| A skill this machine lacks | Installs it. A skill of a source comes from that source, and an account skill from your account repo. |
| A skill at a newer version | Updates it to that version. |
| A skill this machine has | Places it in the configurations the snapshot names, and takes it out of the others. Only the configurations agentx detects on this machine count. |
| A skill it cannot install | Skips it, and prints why. |
| MCP servers and plugins | Nothing, for now. |

Apply never deletes a skill. A skill in your library that the snapshot does not list stays as it is.

If you deleted a skill's folder from your library by hand, apply skips that skill and prints the command that brings it back.

Apply only moves a skill forward:

- A skill that is newer on this machine than in the snapshot stays at its version.
- A skill you edited and did not publish stays as it is. Apply skips it and tells you to run [`agentx skill update <name>`](/cli/skill#a-skill-you-edited), which merges your edits with the newer version.
- A skill whose history went another way on this machine is skipped too. Run `agentx skill update <name>` to merge it.

Clients that read your library, such as Codex, Cursor and Gemini CLI, see every skill in it, whatever the snapshot says.

To install your account skills, apply needs your account repo. The snapshot's settings bring it along.

One repository can have more than one URL. Your laptop may reach your account repo over SSH, as `git@github.com:you/agentx-account.git`, while a cloud agent reaches it over HTTPS, as `https://github.com/you/agentx-account`, with a token that can only read. Apply treats both as your account repo, because they have the same host and path. When the snapshot's account repo is the same repository as this machine's, apply keeps this machine's URL, so each machine goes on reaching it its own way. When the snapshot names another repository, apply switches this machine to that one. A host alias from your SSH configuration, such as `github-work`, does not count as the host it stands for here, because apply reads no SSH configuration.

The report groups the skills by what apply did with them, and names the agents each one is placed in now:

| Section | Meaning |
|---|---|
| Skills added | This machine did not have the skill. Apply installed it and placed it. |
| Skills updated | Apply moved the skill to the version the snapshot names, or to the latest version. |
| Placements changed | The skill was at its version. Apply only placed it in, or took it out of, agents. |
| Skills skipped | Apply left the skill as it is. Each line says why. |

A section with nothing in it is left out. The last line counts the skills that were already at their version and placed as the snapshot says. "Agents enabled" lists the agents detected on this machine that the snapshot's settings do not disable.

Apply the same snapshot again and it changes nothing: every skill is already up to date, or skipped for the same reason as before. Apply fetches nothing for a skill the snapshot names at an exact version. It fetches a skill that follows the latest version again, and moves it forward when a newer version exists. It installs a skill it skipped once the reason is gone.

Apply adds every source of the settings, whether a skill of the snapshot comes from it or not, so you can install from any of them right away. It keeps each source's [pin](/cli/source#pin-a-source). A source that this machine has already added and fetched is not fetched again, so applying the same snapshot a second time does not reach the network for it.

If apply cannot reach a source, it prints a warning with git's reason and goes on: the other sources and the skills are still applied, and apply still succeeds. Its report lists an `agentx source add` line for each such source:

```text
warning: could not add a source of the imported settings: https://github.com/example/private: git fetch: fatal: could not read Username for 'https://github.com': terminal prompts disabled
...
Sources not added (1)
  agentx source add https://github.com/example/private#main
```

Fix the cause, such as a missing [credential](/cli/source#credentials), then run the line as printed, or apply the snapshot again. The line keeps the source's pin, and apply quotes a URL or pin where needed, so you can paste it into bash or zsh.

If apply stops part way, for example because the machine shut down, the next agentx command finishes the change apply was making. Apply the snapshot again to apply the rest, the sources it did not add included.

## Keep a snapshot on your account repo

Instead of a file, save can write the snapshot to your [account repo](/account-repo), on the branch `machines/<machine id>`, and apply can read it from there. The branch holds one file, `snapshot.json`, the same file a save to a file writes. agentx writes to the account repo only when you name a machine with `--machine`, and never on its own.

The snapshot on the branch keeps each MCP server's command, arguments and URL, as a snapshot file does, and these can hold a token. Anyone who can read your account repo can read them, a cloud agent's read-only token included. Keep the account repo private, and give read access only to people and agents you trust with those values.

### Back up this machine

Save to this machine's id. `agentx snapshot save --help` prints it, and so does [`agentx machine`](/cli/machine):

```sh
agentx snapshot save --machine 0123456789abcdef0123456789abcdef
```

```text
✓ saved the snapshot of the settings and 12 skills to machines/0123456789abcdef0123456789abcdef on the account repo at 4c2e9a1
```

Each save writes one commit and pushes it. agentx never forces the push. If the snapshot is unchanged since the last save, agentx pushes nothing and says so.

### Seed another machine

Save to another machine's branch to give that machine this machine's skills. To give your cloud agents the skills of this machine, save to the [cloud machine](https://github.com/grundmanise/agentx/blob/main/GLOSSARY.md):

```sh
agentx snapshot save --machine cloud
```

To change one skill on the cloud machine later, see [Turn skills on for your cloud agents](/cli/skill#turn-skills-on-for-your-cloud-agents).

### Restore from the account repo

On the machine to restore, add your account repo, then apply the branch:

```sh
agentx source add <url> --account
agentx snapshot apply --machine 0123456789abcdef0123456789abcdef
```

Apply reads the snapshot from that one branch and pushes nothing, so a token that can only read your account repo is enough. It then applies the snapshot as it applies a file: it asks once, restores the settings, installs each skill and places it where the snapshot says. Without a terminal, pass `--yes`, see [Confirm without a terminal](#confirm-without-a-terminal). To set up a new computer from another machine, apply that machine's branch once. After that, the two machines are independent.

If the account repo has no branch for that machine, apply stops with exit code 5. If another machine or the web app changed the branch since agentx read it, a save stops with exit code 6 and pushes nothing: run it again.

## Confirm without a terminal

Apply changes your settings and your skills, so it asks first. Pass `--yes` to answer in advance:

```sh
agentx snapshot apply ~/snapshot.json --yes
```

Use `--yes` in scripts, with `--json`, and wherever there is no terminal. Without `--yes`, apply exits with code 6 and changes nothing in these cases. It does the same when you answer anything other than `y` or `yes`.

## When applying is refused

| Exit code | Cause |
|---|---|
| 3 | The account repo cannot be reached. |
| 5 | The file is not there, or the account repo has no branch for the machine you named. |
| 6 | The file is not a valid agentx snapshot: it is damaged, larger than 8 MiB, from an agentx version this one cannot read, holds no settings, or holds a setting or skill entry agentx would not write. The message names the problem. Save the file again on the other machine, or upgrade agentx. |
| 6 | The file was written by an earlier version of agentx. Apply no longer reads that format. Save the file again on the other machine with this version of agentx. |
| 6 | With `--machine`: no account repo is set, or the machine's branch holds no `snapshot.json`. Add the account repo with `agentx source add <url> --account`. |
| 6 | You answered no, or apply could not ask (no terminal, or `--json`) and you did not pass `--yes`. |

A refused apply changes nothing: your settings and your skills stay exactly as they were. A skill apply skips does not make it fail: apply goes on with the others and exits with code 0.
