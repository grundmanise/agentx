---
title: "Account remote"
description: "Publish your forks to a Git repository you own, so your other machines can install them."
---

The account remote is a Git repository you own, such as a private repository on GitHub. [Publish](/cli/skill#publish-a-skill) a fork to it from one machine, [install it on another](/cli/skill#install-your-skills-on-another-machine), and [take in what you publish later](/cli/skill#take-in-what-another-machine-published) with `agentx skill update`. Only forks travel: managed skills, update checks and sources stay on each machine.

The account remote is the [source](/cli/source) you add with `--account`: it holds one branch per fork, and `agentx source list` shows it with `(account)`. Create an empty repository on your Git host, then add it with [`agentx source add <url> --account`](/cli/source#add-your-account-remote). Detach it with `agentx source remove <url>`: your forks and their history stay, and nothing on the remote changes.

A machine without a remote keeps the whole history of every fork: `agentx skill history` and `agentx skill diff` work without one. Attach a remote when you want a backup, or a second machine.

## Two forks with one name

Every fork has a permanent id. A skill you create on two machines under the same name is two forks, with two ids. agentx never mixes them: once one is published, publishing or updating the other stops with exit code 6:

```text
error: the account remote's skills/release-notes is a different fork than release-notes on this machine, so release-notes cannot be published
hint: rename yours with 'agentx skill rename release-notes <new>', then publish that one
```

[Rename](/cli/fork#rename-a-fork) yours, then publish it under its new name. For every exit code `agentx skill publish` uses, see [Exit codes](/cli/skill#exit-codes).
