---
title: "Account remote"
description: "Publish your forks to a Git repository you own, and install them on your other machines."
---

The account remote is a Git repository you own, such as a private repository on GitHub. Publish a fork to it from one machine, install it on another, and [take in what you publish later](/cli/skill#take-in-what-another-machine-published) with `agentx skill update`. Only forks travel: managed skills, update checks and sources stay on each machine.

The account remote is the [source](/cli/source) you add with `--account`: it holds one branch per fork, and `agentx source list` shows it with `(account)`. Create an empty repository on your Git host, then add it with [`agentx source add <url> --account`](/cli/source#add-your-account-remote). Detach it with `agentx source remove <url>`: your forks and their history stay, and nothing on the remote changes.

A machine without a remote keeps the whole history of every fork, with commit and diff. Attach a remote when you want a backup, or a second machine.

## Publish a fork

```sh
agentx skill publish release-notes
```

```text
✓ published release-notes as 4c2e9a1
```

- Publishing pushes your commits, and nothing else. Commit your edits first with [`agentx skill commit`](/cli/fork#commit-your-edits). A fork with uncommitted edits still publishes its commits, and agentx names it with a warning.
- `agentx skill publish` with no name publishes every fork with commits the remote does not have.
- Each fork goes to its own branch, `skills/<name>`. Publishing one fork leaves your other forks' commits where they are.
- When another machine published commits of the fork first, agentx takes them in before it pushes, as [`agentx skill update`](/cli/skill#take-in-what-another-machine-published) does. Commit or discard your edits first: a fork with uncommitted edits stops with exit code 6.
- agentx never forces a push. When the remote rejects one, for example because another machine published meanwhile, run `agentx skill update <name>`, then publish again.
- When taking them in conflicts, the merge waits and the fork is not pushed: see [Resolve a conflict](/cli/fork#resolve-a-conflict).
- Nothing is pushed for you. Run `agentx skill publish` each time you want your commits on the remote.
- To delete a fork's branch from the remote, remove the fork with [`agentx skill remove <name> --remote`](/cli/fork#remove-a-fork).

## Install a fork on another machine

On a second machine, add the same remote with `agentx source add <url> --account`, then list the forks it holds that this machine has not installed:

```sh
agentx skill list --remote
```

```text
1 skill
  pdf  managed  current  https://github.com/anthropics/skills/skills/pdf  4 placements
2 installable forks on the account remote
  release-notes  fork  installable  https://github.com/acme/skills/release-notes
  standup        fork  installable  (none)
Install one with agentx skill add --from-account <name>.
```

- `--remote` fetches the remote first. A remote Git cannot reach stops with exit code 3.
- Each row names the upstream the fork's own commits record, or `(none)` for a skill you created with `agentx skill new`.
- A branch on the remote that agentx cannot install as a fork is left out with a warning: one whose name is not a valid skill name, or whose history records no fork id.

Install one:

```sh
agentx skill add --from-account release-notes
```

```text
✓ added https://github.com/acme/skills at 7d1e0b2: 3 skills; you can write to it
✓ installed release-notes from the account remote at 4c2e9a1: 1 placement
  claude-code  symlink  ~/.claude/skills/release-notes -> ~/.agents/skills/release-notes
```

- It is the same fork, with its id and its whole history. Commit here and publish, and the commits go to the same branch.
- agentx places it into every enabled configuration, as `agentx skill add` does. Pass `--to <configuration>` to choose, and `--copy` for copies.
- When this machine has not added the fork's upstream source, agentx adds it, so that [`agentx skill check-updates`](/cli/skill) finds the fork's updates here too. A source it cannot fetch does not stop the install: run the `agentx source add` line the warning prints.

### When the library already holds the name

- **A managed copy of the same upstream, unedited**: the fork takes its place. Its placements stay as they are: symlinks now lead to the fork, and a copy keeps the managed version until `agentx skill place <name>` refreshes it. Files Git ignores in it, such as a `.DS_Store`, move into the fork.
- **A managed skill with an update merge pending**: agentx stops with exit code 4. Finish the merge, or give it up with `agentx skill update <name> --abort`, then install again.
- **A managed copy with your edits, or any other folder**: agentx stops with exit code 6 and changes nothing. Pass `--keep-local` to move the folder into the fork as it is: its whole content replaces the fork's as uncommitted edits, and files Git ignores stay with it. A folder older than the fork's latest commits then shows those commits undone, so check the edits with `agentx skill diff <name>` first. Then keep the edits with [`agentx skill commit`](/cli/fork#commit-your-edits).
- **A symlink**: agentx stops with exit code 6, even with `--keep-local`. Remove the link, then install again.

## Two forks with one name

Every fork has a permanent id. A skill you create on two machines under the same name is two forks, with two ids. agentx never mixes them: once one is published, publishing or updating the other stops with exit code 6:

```text
error: the account remote's skills/release-notes is a different fork than release-notes on this machine, so release-notes cannot be published
hint: rename yours with 'agentx skill rename release-notes <new>', then publish that one
```

[Rename](/cli/fork#rename-a-fork) yours, then publish it under its new name.

## Exit codes

- `1`: `skill add --from-account` is given no name, a source, `--name`, `--all`, `--except` or `--fetch`; or `--keep-local` is given without `--from-account`.
- `3`: Git cannot reach the account remote.
- `4`: a fork has a merge waiting, or the publish left one waiting for you to [resolve](/cli/fork#resolve-a-conflict); or the managed skill a fork would take the place of has an update merge pending.
- `5`: the name is not a skill of this machine; the remote holds no fork of that name to install; or the fork to install, or the folder `--keep-local` keeps, has no `SKILL.md`.
- `6`: no account remote is set; the skill is not a fork; the fork to install is installed already, or the library holds a symlink, edits or a folder of its own at its name; the remote's branch of that name is [another fork](#two-forks-with-one-name), names no fork id, or shares no commit with yours; the fork has uncommitted edits and the remote has something new; the remote rejected the push; the fork's worktree is missing, needs repair or is not on its branch; or the fork, or its branch on the remote, changed while it was being published.
- `7`: another agentx command is running. Retry when it finishes.
- `8`: the account repo in agentx home cannot be read or written. Run `agentx doctor`.
