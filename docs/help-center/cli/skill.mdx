---
title: "agentx skill"
description: "Install, place, update, publish and remove skills, and see what is in your library."
---

Your library is one directory, `~/.agents/skills`, that holds every skill agentx manages for you. Installing a skill puts it there once and links it into each agent client, so every client sees the same files and an update reaches all of them at once.

## Install a skill

```sh
agentx skill add anthropics/skills --name pdf
```

```text
✓ added https://github.com/anthropics/skills at 8c41d07: 17 skills; write access unknown
✓ installed pdf from https://github.com/anthropics/skills under skills/pdf at 3f2a9c1, source fetched 2026-09-22T10:00:00Z: 4 placements
  claude-code  symlink  /home/me/.claude/skills/pdf -> /home/me/.agents/skills/pdf
  codex        library  /home/me/.agents/skills/pdf
  cursor       symlink  /home/me/.cursor/skills/pdf -> /home/me/.agents/skills/pdf
  gemini-cli   library  /home/me/.agents/skills/pdf
  always available to universal clients: codex, gemini-cli
```

Each row is one client's placement: the link or copy in its own skills directory, or the library entry itself for a client that reads the library. Cursor also reads Claude Code's skills directory, so it sees the skill there too; that path is Claude Code's row.

To install your own skills that another machine published to your account remote, run `agentx skill add --name <name>` or `agentx skill add --all` with no source. See [Install your skills on another machine](#install-your-skills-on-another-machine).

If the source is not on this machine yet, `skill add` adds it first, as [`agentx source add`](/cli/source) would. The source stays added even if the install then fails. Name the source by its URL for this: a source id only works for a source you already added.

If you removed the source and a skill installed from it is still in your library, installing by its id tells you the command that adds it again:

```text
error: no source with id 1c9d0b7e4a2f6d38: https://github.com/anthropics/skills was removed, and the skills installed from it still name it
hint: run 'agentx source add https://github.com/anthropics/skills' to add it again
```

A source you already added is not fetched again. The install reads what that source last fetched, whether you fetched it or the [desktop app's background process](/cli/serve#update-checks) did, and the result says when that fetch was. Add `--fetch` to fetch the source again first, or run `agentx source fetch`:

```sh
agentx skill add anthropics/skills --name pdf --fetch
```

To install from another branch or tag than the one the source is pinned to, change the pin with `agentx source add <url>#<ref>` first.

Name the skill with `--name` when the source holds more than one. `--name` and `--except` match the `name` in the skill's `SKILL.md` frontmatter, ignoring case, or the directory name when there is no `name`, as the vercel skills CLI does. If a path already narrows it to a single skill, leave `--name` out:

```sh
agentx skill add anthropics/skills/skills/pdf
```

### Install several at once

Give `--name` once for each skill you want:

```sh
agentx skill add anthropics/skills --name pdf --name xlsx --name docx
```

Or take the whole source and leave out what you do not want:

```sh
agentx skill add anthropics/skills --all --except artifacts-builder
```

`--all` and `--name` do not mix, and `--except` needs `--all`. Skills install in the order the source lists them, whatever order you name them in. `--all` works with a source you have not added yet too: it is added once, and then every skill of it installs.

One command installs them all: the files come down in one fetch, the versions are recorded in one write to the account repo, and the whole run is one change agentx can finish after an interruption. Thirty skills cost the same git work as one; the time they take is the time their files take.

If one skill cannot be installed, the rest still land. agentx names the one it skipped and why, and exits non-zero:

```text
warning: xlsx: the library already holds xlsx at /home/me/.agents/skills
✓ installed pdf from https://github.com/anthropics/skills under skills/pdf at 3f2a9c1, source fetched 2026-09-22T10:00:00Z: 4 placements
  ...
error: 1 of 3 skills could not be installed: xlsx: the library already holds xlsx at /home/me/.agents/skills
```

agentx also refuses a skill whose directory in the source carries a control character, or opens or closes with a space:

```text
error: pdf comes from " skills/pdf", which is not a directory the account repo can record
hint: the import commit that records where a skill came from carries the directory on one line of a trailer, so it can hold no control character and no surrounding space; rename the directory upstream, or install another skill
```

agentx records where a skill came from on one line of its commit. A directory name that does not fit on one line would be read back as a different directory, or as none at all, leaving a skill you could never update. Ask the source to rename the directory, or install a different skill.

### Clients that see every skill

Some clients, such as Codex and Gemini CLI, read the library directly. They are universal clients: they get no link of their own, because the library entry is what they see. A client is also universal when:

- its skills directory is a symlink to the library, or the library is a symlink to it, since both are then one directory;
- it reads such a directory. Cursor reads Claude Code's skills directory, so once `~/.claude/skills` is a symlink to the library, Cursor reads the library as well.

Every other client gets a symlink in its own skills directory, pointing at the library.

A universal client sees every skill in your library, even when you disabled it with `agentx config disable` or left it out of `--to`. Each install ends with a line naming every universal client installed on this machine, since the skill is always available to them whatever you chose:

```text
  always available to universal clients: codex, gemini-cli
```

The line is left out when no universal client is installed. To take a skill away from the universal clients, remove it from the library, see [Clients that read the library](#clients-that-read-the-library).

### Choose where it goes

By default a skill is placed in every enabled configuration. Name the ones you want instead:

```sh
agentx skill add anthropics/skills --name pdf --to claude-code --to cursor
```

`--to` replaces the default targets for that install, including configurations you have disabled with `agentx config disable`. It decides which clients get a placement; the universal clients see the skill whatever it names.

### Copy instead of link

```sh
agentx skill add anthropics/skills --name pdf --copy
```

Use `--copy` for a client that cannot follow a symlink. agentx remembers which configurations hold a copy and keeps them that way: installing the skill again, `agentx skill place` and `agentx config enable --place-all` give those configurations a copy even without `--copy`.

### What happens to what is already there

- A library directory holding exactly this version is adopted: agentx records where it came from and changes nothing on disk.
- A library directory holding anything else stops that skill with exit code 6. Remove it, or keep it and install under another name later. In a run of several skills only that skill is stopped.
- A placement that already points at the library is left alone.
- A placement that is a real directory holding exactly this version is replaced by a link and reported as adopted. A copy agentx placed there itself stays a copy and is not reported as adopted.
- If the library entry is itself a link to that client's directory, for example `~/.agents/skills/pdf` linked to `~/.claude/skills/pdf`, the client already reads the library there: agentx leaves it as it is, reports it as placed, adopts nothing, and with `--copy` records no copy.
- A copy agentx placed that is different from the library is kept exactly as it is and skipped, with a warning. See [A copy that differs from the library](#a-copy-that-differs-from-the-library).
- A placement that is a link somewhere else is left alone, even if what it points at holds the same files: where your skill lives is your choice.
- Anything else in the way is left untouched, with a warning naming the path.
- A client skills directory agentx cannot write – one owned by somebody else, one on a read-only mount, or one macOS has not granted access to – is skipped with a warning. The rest of the install still happens, and the summary counts the placements it skipped.

Your files are never overwritten by an install.

If two commands try to install the same name at once, one of them wins and the other is refused. The one that loses leaves nothing behind: no half-written directory, and nothing for the next command to clean up.

### A copy that differs from the library

A copy agentx placed stops matching the library when you edit the copy or when the skill in the library changes. `agentx skill place` and `agentx config enable --place-all` keep that copy exactly as it is and skip it, with a warning:

```text
warning: cursor's copy of pdf is different from the library, so it was left unchanged (/home/me/.cursor/skills/pdf)
  to replace it with the library version: agentx skill remove pdf --from cursor && agentx skill place pdf --to cursor --copy
```

Installing the skill again keeps and skips a copy you edited the same way, with the same warning. When the skill in the library changed, the install stops with exit code 6 before it reaches the copy, as described in [What happens to what is already there](#what-happens-to-what-is-already-there).

The summary counts the copy as a skipped placement. agentx does not record what a copy held when it placed it, so the warning does not say which side changed.

To replace the copy with the library version, run the commands on the second line of the warning. Removing the copy deletes what it holds, so save anything you want to keep first. `--copy` makes the new placement a copy again, as agentx had recorded for that client. For a skill whose name starts with `-`, the commands put the name last, after `--`, for example `agentx skill remove --from cursor -- -pdf`.

### What is left out of the import

A skill directory holds regular files and directories. Anything else – a symlink or a git submodule inside the skill – is left out, with a warning naming it. The library directory then differs from the upstream one, and what agentx records as the installed version is what it actually installed.

### Install your skills on another machine

Your own skills, the ones you create or fork and then publish to your [account remote](/cli/source#add-your-account-remote), install on another machine from that remote. Add the same remote there with `agentx source add <url> --account`, then list the skills it holds that this machine has not installed:

```sh
agentx skill list --remote
```

```text
1 skill
  pdf  managed  current  https://github.com/anthropics/skills/skills/pdf  4 placements
2 installable skills on the account remote
  release-notes  managed  installable  ssh://git@github.com/you/forks (account)
  standup        managed  installable  ssh://git@github.com/you/forks (account)
Install one with agentx skill add --name <name>, or all of them with agentx skill add --all.
```

- `--remote` fetches the remote first. A remote Git cannot reach stops with exit code 3.
- Each row names your account remote, where the skill is published to, and, for a skill you forked from an installed skill, where it came from after `from`, as `agentx skill list` shows it. A skill you created with `agentx skill new` has no upstream.
- A branch on the remote that agentx cannot install is left out with a warning: one whose name is not a valid skill name, or whose history records no fork id.
- The old name of a skill you [renamed](/cli/fork#rename-a-skill-of-your-own) is not listed on a machine that holds the renamed skill, while the remote still holds it.

Run `agentx skill add` with no source to install from the account remote. Name a skill with `--name`, once for each:

```sh
agentx skill add --name release-notes
```

```text
✓ installed release-notes from the account remote at 4c2e9a1: 1 placement
  claude-code  symlink  /home/me/.claude/skills/release-notes -> /home/me/.agents/skills/release-notes
```

Or install every skill the account remote holds that this machine lacks, and leave out what you do not want with `--except`:

```sh
agentx skill add --all --except standup
```

- It is the same skill, with its id and its whole history. Edit it here and publish, and your changes go to the same branch.
- agentx fetches the account remote every time, so `--fetch` does not apply. A remote Git cannot reach stops with exit code 3.
- `--name` and `--except` match the skill's name exactly.
- agentx places each skill into every enabled configuration, as for a source. Pass `--to <configuration>` to choose, and `--copy` for copies.
- When this machine has not added the upstream source of a skill you forked, agentx adds it first and prints its `✓ added <url> at <commit>: <n> skills` line, so that [`agentx skill check-updates`](#check-for-updates) finds the skill's updates here too. A source it cannot fetch does not stop the install: run the `agentx source add` line the warning prints.
- A skill that cannot be installed does not stop the others: agentx names it in a warning and installs the rest. The command then exits with that skill's exit code, or `6` when several skills failed for different reasons.

#### When the library already holds the name

- **A managed copy of the same upstream, unedited**: the skill from the account remote takes its place. Its placements stay as they are: symlinks now lead to the new skill, and a copy keeps the managed version until `agentx skill place <name>` refreshes it. Files Git ignores in it, such as a `.DS_Store`, move along.
- **A managed skill with an update merge pending**: agentx stops with exit code 4. Finish the merge, or give it up with `agentx skill update <name> --abort`, then install again.
- **A managed copy with your edits, or any other folder**: agentx stops with exit code 6 and changes nothing. Move the folder aside, or remove the skill with `agentx skill remove <name>`, then install again.
- **A symlink**: agentx stops with exit code 6. Remove the link, then install again.

## Place a skill you already have

Put a skill the library already holds into another client:

```sh
agentx skill place pdf --to cursor
```

```text
✓ placed pdf in 1 configuration
  cursor  symlink  /home/me/.cursor/skills/pdf -> /home/me/.agents/skills/pdf
  always available to universal clients: codex, gemini-cli
```

The first line counts the configurations you placed into. Each client you named gets one row, its own placement, as after an install. If agentx left a client's path alone and that client still sees the skill through another client's skills directory, its row shows that path instead, so the output still tells you the client has the skill.

Name each client with `--to`, once for each. Without `--to`, agentx places the skill into every enabled client and puts back what `agentx skill list` flags there; see [Put back placements](#put-back-placements). Add `--copy` for a client that cannot follow a symlink; agentx remembers the choice, as it does for `agentx skill add --copy`. To turn a recorded copy back into a symlink, take it away with `agentx skill remove pdf --from cursor`, then place the skill again with `agentx skill place pdf --to cursor`.

What is already at the path decides what happens:

- A link that already points at the library is left alone.
- A directory holding exactly this version is adopted.
- A directory holding anything else stops the command, unless you add `--force`, which deletes what it holds. See [When the directory differs from the library](#when-the-directory-differs-from-the-library).
- Anything else, such as a link of your own, is left where it is, with a warning.
- If the library entry is itself a link to that client's directory, for example `~/.agents/skills/pdf` linked to `~/.claude/skills/pdf`, the client already reads the library there. agentx leaves it as it is, reports it as placed, adopts nothing, and with `--copy` records no copy.

An adopted directory becomes one agentx will delete when you remove the skill, so the run names every path it adopted. This holds with `--copy` too.

A universal client, such as Codex or Gemini CLI, reads the library directly. Placing into one makes no second entry: it already sees the skill, and the last line names every universal client whichever clients you place into.

Use `skill place`, not `skill add`, for a skill that is already in your library. `skill add` installs from a source, so given the name of a library skill it stops with exit code 1 and names the command to run instead:

```text
error: pdf is already in the library; skill add installs a skill from a source
hint: to place it in more clients, run 'agentx skill place pdf'
```

The hint keeps the `--to` and `--copy` you gave. Without `--to`, it places the skill into every enabled client. A source always comes first: a source URL, `owner/repo` or a source id installs from that source, even when a skill in your library has the same name.

## Remove a skill

From one client:

```sh
agentx skill remove pdf --from cursor
```

```text
✓ removed pdf from cursor: 1 placement
  cursor  symlink  /home/me/.cursor/skills/pdf
```

From the machine altogether:

```sh
agentx skill remove pdf
```

```text
✓ removed pdf from the library: 4 placements
  claude-code  symlink  /home/me/.claude/skills/pdf
  cursor       copy     /home/me/.cursor/skills/pdf
  codex        library  /home/me/.agents/skills/pdf
  gemini-cli   library  /home/me/.agents/skills/pdf
  deleted /home/me/.agents/skills/pdf and refs/heads/managed/pdf
```

Without `--from`, agentx takes away every placement, the library directory, the record of where the skill came from and what the settings remembered about it. With `--from <client>`, only those clients' placements go; the library keeps the skill.

While a skill has a [merge pending](#when-your-edits-conflict), removing it from the machine stops with exit code 4 and removes nothing. Removing it from one client works as usual.

From every client, by name:

```sh
agentx skill remove pdf --from universal
```

This is the same removal as leaving `--from` out, with the same output. A universal client reads the library entry itself, so removing a skill from the universal clients means removing it from the library, which takes it from every client.

Give `--from universal` on its own. Next to a client that is not universal, it stops with exit code 1 and removes nothing. Next to a universal client, it is refused as that client is; see [Clients that read the library](#clients-that-read-the-library).

### What agentx will and will not delete

agentx deletes a placement only when it made it:

- a symlink pointing at the library directory, and
- a copy agentx placed and recorded.

Everything else is left exactly where it is and named in the output:

- a directory you made by hand,
- a link of yours pointing somewhere else, even when following it ends up in the library,
- a directory holding the same version that agentx never recorded as a copy,
- a file.

agentx decides by the name a link holds, never by where following it leads, so a link of yours is yours whatever it resolves to:

```text
warning: /home/me/.claude/skills/pdf points at /home/me/mylinks/pdf, not at /home/me/.agents/skills/pdf and was left as it is; it no longer leads to pdf
warning: /home/me/.cursor/skills/pdf is a directory agentx did not place there and was left as it is; cursor still sees it
✓ removed pdf from the library: 2 placements, 2 placements left in place
  ...
```

Here `~/mylinks/pdf` points at the library entry, so once the removal deletes that entry your link stays but no longer leads to the skill, and the warning says so. A link of yours that does not lead through anything the removal deletes keeps working, and the warning says which client still sees the skill.

A copy agentx recorded is removed as you asked, even when it no longer holds the library's version of the skill. agentx warns, naming whose copy it was and its path, rather than letting the content go quietly:

```text
warning: cursor's copy of pdf was different from the library; removing it deleted those changes (/home/me/.cursor/skills/pdf)
```

Take a copy of anything you want to keep before removing it.

### Clients that read the library

Universal clients, such as Codex and Gemini CLI, read `~/.agents/skills` directly, so there is no placement of their own to remove. A skill leaves every universal client at once or none of them:

```sh
agentx skill remove pdf --from codex
```

```text
error: codex reads the library directly, so pdf cannot be removed from it alone
hint: take pdf off the machine with 'agentx skill remove pdf --from universal', which removes it from claude-code, codex, cursor, gemini-cli
```

agentx refuses before it changes anything. It also refuses when `--from` names other clients as well, `universal` included, and when the universal client is disabled.

The hint lists every client the removal would take the skill from:

- every client that sees the skill through the library, or through a link or copy agentx would delete, including one that reads another client's skills directory, as Cursor reads Claude Code's;
- a client whose link of yours ends up in the library: the removal leaves your link, but the link no longer leads anywhere.

A directory of your own is not counted, since the removal leaves it. Run the command in the hint to remove the skill everywhere, or keep the skill.

A client that is universal because it reads a skills directory linked to the library is refused the same way, even when a link in its own skills directory is still there. For example, with `~/.claude/skills` a symlink to the library, Cursor reads the library through it. So `agentx skill remove pdf --from cursor` stops with exit code 6, `cursor reads the library directly, so pdf cannot be removed from it alone`, and leaves `~/.cursor/skills/pdf` where it is. Delete that link yourself if you no longer want it, or take the skill off the machine with `--from universal`.

### After a removal

A client may still see a skill through another client's directory: Cursor reads Claude Code's skills directory, for instance. agentx rescans and reports what the client sees now, so the output tells you whether the skill is really gone from it.

Removing a skill from the machine warns for every client that still sees it afterwards, naming the path:

```text
warning: codex still sees pdf at /home/me/.codex/skills/pdf, which agentx did not place there
```

Universal clients, such as Codex and Gemini CLI, read the library, so removing the library entry is all agentx can do for them. A directory of their own under the same name stays, and the warning says where it is.

### A skill whose library directory is gone

If a managed skill's directory was deleted from the library outside agentx, `agentx skill list` warns about it until you install it again or remove it. Removing it always works, whatever the source holds now:

```sh
agentx skill remove pdf
```

```text
✓ removed pdf, which the library no longer held: 2 placements
  claude-code  symlink  /home/me/.claude/skills/pdf
  cursor       copy     /home/me/.cursor/skills/pdf
  deleted refs/heads/managed/pdf
```

agentx deletes the record of where the skill came from and the placements it made, by the same rules as any removal, and takes the skill out of the settings.

- A copy placement may be the last copy of the skill on your machine. If it differs from the version the skill was installed at, or agentx cannot tell which version that was, agentx still removes it and warns you that your changes went with it, as in `cursor's copy of pdf was different from its base version; removing it deleted those changes`. Copy anything you want to keep out of it first.
- If a directory without a `SKILL.md` is still in the library under that name, agentx leaves it where it is and says so.
- `--from <client>` is refused with exit code 6 for such a skill: with nothing in the library, there is no skill for one client to keep. Leave `--from` out.

### Your own skills

Removing one of your own skills without `--from`, or with `--from universal`, also deletes its worktree and its branch, and `--remote` deletes its branch on the account remote too: see [Remove a skill of your own](/cli/fork#remove-a-skill-of-your-own). `--from <client>` takes its placement away as for any skill.

`--remote` applies only to your own skills, the ones on your account remote. For a skill of another source, or one with no source, agentx refuses it with exit code 6 and changes nothing: remove the skill from this machine with `agentx skill remove <name>`.

## List your skills

```sh
agentx skill list
```

```text
5 skills
  docx    managed    modified, source removed  https://github.com/me/skills/docx                                                               2 placements
  my-pdf  managed    modified                  ssh://git@github.com/you/forks (account), from https://github.com/anthropics/skills/skills/pdf  4 placements
  notes   managed    current                   ssh://git@github.com/you/forks (account)                                                        4 placements
  pdf     managed    current                   https://github.com/anthropics/skills/skills/pdf                                                 4 placements
  todo    unmanaged  -                         (none)                                                                                          2 placements
```

Each row shows the skill, its kind, whether it holds edits you have not published, its source and how many placements it has, one per client that sees it.

The kind is one of two:

- `managed`: a skill agentx keeps. Either installed from a source, with a version it can compare against; or one of your own, which you created with [`agentx skill new`](/cli/fork#create-a-skill), forked with [`agentx skill fork`](/cli/fork#fork-a-skill) or installed from your account remote, with a history of its own in the account repo.
- `unmanaged`: a directory in the library agentx did not install. It is inventoried and otherwise left alone.

The source column shows where the skill is published to:

- A skill of a shared source shows the source's URL and the folder in it, as `pdf` does above. Its updates come from there.
- One of your own skills shows your [account remote](/cli/source#add-your-account-remote), marked `(account)` as `agentx source list` marks it, or `account remote not set` until you add one. A skill you forked from an installed skill also shows where it came from, its upstream, after `from`, as `my-pdf` does above, and takes the updates of its upstream.
- An unmanaged skill shows `(none)`.

The state column shows:

- `current` or `modified`: whether the skill holds edits you have not published yet. A skill of a shared source is compared with the version it was installed at, or the one you last [published to its source](#publish-edits-to-a-shared-source). One of your own skills is compared with what you last published to your account remote, as agentx last fetched it: it stays `modified` until you [publish its edits](#publish-a-skill), including edits an update or a fork recorded on it. One you never published is `current` until you edit or update it. One another machine removed from the account remote, or renamed there, is compared with what the account remote last held of it. Every change counts, whatever tool made it: a file you edited, added or deleted, but also a file made executable, a file replaced by a symlink and a symlink added. Files git ignores do not count: see [Files that do not count](#files-that-do-not-count). See what changed with [`agentx skill diff`](#see-what-you-changed).
- `displaced`: a client that should see the skill through a link from its own skills directory has a real directory there instead, which is what an installer that copies over links leaves. For a client you placed a copy in, it is the other way round: a link to the library where the copy should be. Put it back with [`agentx skill place <name>`](#put-back-placements).
- `missing`: an enabled client has nothing of the skill in its own skills directory, because you placed the skill with `--to`, removed it with `--from`, or the placement was deleted. Place it in one client with `agentx skill place <name> --to <client>`, or in every client it is missing from with [`agentx skill place <name>`](#put-back-placements). Universal clients and disabled clients are never missing a skill.
- `source removed`: the source the skill came from is no longer added on this machine. The skill keeps working, stays where it is and keeps its record of where it came from. Add the source again to clear it: see below.
- `upstream removed`: the last [update check](#check-for-updates) found the skill gone from its source. The skill stays as it is and is never updated. The next check that finds it back in the source clears the state.
- `remote removed`: one of your own skills that the account remote held and no longer holds, because another machine removed it or renamed it. The skill stays as it is, and a publish of all your skills leaves it out. Remove it here with `agentx skill remove <name>`, or put it back on the account remote with `agentx skill publish <name>`: see [Remove a skill of your own](/cli/fork#remove-a-skill-of-your-own). Removing or replacing the account remote clears this state.
- `update available`: the last update check found a newer version of the skill in its source. Nothing changed in your library; apply the update with [`agentx skill update <name>`](#update-a-skill), or read it first with `agentx skill diff <name> --update`.
- `merge pending`: an update of the skill found your edits conflicting with it. The update left your library directory as it was, and it applies nothing until you resolve the merge with Git and update again, or give it up. See [When your edits conflict](#when-your-edits-conflict).

Add `--remote` to fetch your [account remote](/cli/source#add-your-account-remote) first and list after these rows the skills it holds that this machine has not installed, as `installable`. Install one with `agentx skill add --name <name>`, or all of them with `agentx skill add --all`: see [Install your skills on another machine](#install-your-skills-on-another-machine).

A skill can be in more than one state at once, so the row names each of them: `modified, source removed` is a skill you edited whose source you then removed. `displaced` and `missing` are information only: they never make a command fail.

If a managed skill's directory is deleted from the library outside agentx, the skill has no row, since there is nothing left to compare or place. `skill list` names it in a warning instead, with two ways out:

```text
warning: pdf is managed in the account repo but the library holds no skill directory for it; run 'agentx skill add https://github.com/anthropics/skills --name pdf' to install it again, or 'agentx skill remove pdf' to stop managing it
```

- Install it again with `agentx skill add`. This works while the source still holds the version you installed. If you fetched the source since and the skill changed upstream, `skill add` refuses and tells you to run `agentx skill remove` first; after that, `skill add` installs the version the source holds now.
- Stop managing it with `agentx skill remove`. This always works: it deletes the skill's record in the account repo and the placements agentx made, and clears the warning.

If the directory is still there but has lost its `SKILL.md`, the warning names it. Move it aside before you install the skill again, since `skill add` does not write over it.

### Bring back a removed source

A managed skill whose source you removed shows `source removed` until you add that source again:

```sh
agentx source add https://github.com/me/skills
```

That clears the state and changes nothing else: the skill, its record and its placements stay exactly as they were. It works with any pin, since a source is identified by its URL. Installing another skill from the source by its URL, or adopting one with [`agentx adopt`](/cli/adopt), adds the source again too.

## See what you changed

Compare a managed skill with the version it was installed at, or the one you last [published to its source](#publish-edits-to-a-shared-source), to see the edits you have not published yet:

```sh
agentx skill diff pdf
```

```text
pdf differs from its base version at 3f2a9c1 in 2 files
diff --git a/SKILL.md b/SKILL.md
index 5d1e2c4..8f0a3b1 100644
--- a/SKILL.md
+++ b/SKILL.md
@@ -3,2 +3,3 @@ name: pdf
 # PDF
 Use this skill to read and fill in PDF forms.
+Always keep the original file.
diff --git a/notes.md b/notes.md
new file mode 100644
index 0000000..2f1c9e0
--- /dev/null
+++ b/notes.md
@@ -0,0 +1 @@
+My own notes.
```

There is one diff per file, and every path is relative to the skill's directory. A file you moved shows as one deleted and one added. A skill that holds exactly its base version prints `pdf matches its base version at 3f2a9c1`. A file that is not UTF-8 text prints as the bytes it holds. Control characters other than the tab, such as the carriage return of a Windows line ending, print as a space, so nothing in a file can control your terminal.

The diff only reads your library: nothing is written to it. A file git ignores is never in the diff, and a file the skill's `.gitattributes` converts, for example to other line endings, is compared as git converts it: see [Files that do not count](#files-that-do-not-count).

A repository nested in the skill, or anything else git cannot record, such as a named pipe, is left out with a warning naming it. Such a skill never matches its base version:

- `skill list` shows it as `modified`;
- the diff ends with the number of paths git cannot record, as in `pdf differs from its base version at 3f2a9c1 only in 1 path git cannot record`;
- `skill update` refuses to apply an update to it until you move the path out of the skill.

A skill agentx did not install has no base version to compare with, so `skill diff` stops with exit code 6. For one of your own skills, `skill diff` shows its unpublished edits instead, against what you last published: see [See what changed](/cli/fork#see-what-changed).

### Files that do not count

agentx compares a skill as git compares a work tree, so the files git ignores never make a skill `modified`, never show in `skill diff`, and are kept by `skill update`:

- files the skill's own `.gitignore` names, such as a `node_modules` directory;
- files your global git ignore file names, `~/.config/git/ignore` or the file your `core.excludesFile` setting points to;
- files your operating system or editor leaves behind, such as `.DS_Store`, `Thumbs.db`, `*.swp` and `*~` backups, while the [`ignore_system_files`](/cli/config) setting is on, which it is by default.

A file that was part of the version you installed always counts, even when an ignore rule names it. The skill's own `.gitattributes` applies too: a file that differs only in line endings the skill asks git to normalise is not a change.

## Get the original back

agentx does not undo edits for you. To discard your edits, remove the skill and add it again:

```sh
agentx skill remove pdf
agentx skill add anthropics/skills --name pdf
```

Removing deletes the skill and every edit you made to it, so run `agentx skill diff pdf` first and save what you want to keep. Adding it again installs the version the source holds, which may be newer than the one you had. Pass `--copy` or `--to` again if you placed the skill that way: removing it forgets those choices.

## Put back placements

Put back the placements `agentx skill list` shows as `missing` or `displaced`, in every enabled client:

```sh
agentx skill place pdf
```

```text
✓ placed pdf in 4 configurations
  claude-code  symlink  /home/me/.claude/skills/pdf -> /home/me/.agents/skills/pdf
  codex        library  /home/me/.agents/skills/pdf
  cursor       symlink  /home/me/.cursor/skills/pdf -> /home/me/.agents/skills/pdf
  gemini-cli   library  /home/me/.agents/skills/pdf
  adopted /home/me/.claude/skills/pdf
  always available to universal clients: codex, gemini-cli
```

- A missing placement is made again: a copy if you placed a copy there before, a link otherwise.
- A link to the library where you placed a copy is replaced with a copy.
- A real directory where the link belongs is replaced with the link when it holds exactly what the library holds, and named as adopted: nothing is lost.

Add `--to` to put back only the clients you name. A link of your own to another directory, a copy you edited, and clients you disabled are left as they are. So is a client's directory that the library entry itself is a symlink to, for example `~/.agents/skills/pdf` linked to `~/.claude/skills/pdf`: that directory is the library's own content.

### When the directory differs from the library

If a real directory where the link belongs holds anything else, for example because another installer copied a different version there or you edited the skill there, replacing it would delete what it holds. `skill place` stops with exit code 6 and changes nothing:

```text
error: /home/me/.claude/skills/pdf is a directory whose content differs from the library's pdf, so nothing was placed
hint: to replace it with the library's version and delete what it holds, run 'agentx skill place pdf --force'; to keep it, move it elsewhere first
```

To replace it with the library version, add `--force`. The directory is deleted and replaced with the link:

```sh
agentx skill place pdf --force
```

```text
✓ placed pdf in 4 configurations
  claude-code  symlink  /home/me/.claude/skills/pdf -> /home/me/.agents/skills/pdf
  codex        library  /home/me/.agents/skills/pdf
  cursor       symlink  /home/me/.cursor/skills/pdf -> /home/me/.agents/skills/pdf
  gemini-cli   library  /home/me/.agents/skills/pdf
  discarded what /home/me/.claude/skills/pdf held
  always available to universal clients: codex, gemini-cli
```

To keep that content instead, move the directory out of the client's skills directory, for example to use it as a skill of your own, then run `skill place` again to put the link back. `--force` never changes the library.

`--force` works with `--to` and `--copy`: it replaces only the directories of the clients `--to` names, and with `--copy` the client gets a copy of the library version.

Only what the directories held when you ran the command is replaced. If a directory or the library changes while `skill place` runs, agentx stops with exit code 6 and changes nothing; run it again. agentx keeps what it replaces until the command is complete, so an interrupted run finishes on the next command and loses nothing.

### What stops it

One of your own skills is placed as `skill add` places it: a directory that differs is left where it is with a warning. `skill place` also puts back its worktree and library symlink, and `--force` adopts what is in its way: see [Recover a skill of your own](/cli/fork#recover-a-skill-of-your-own). A managed skill whose library directory is gone stops with exit code 6: install it again with `agentx skill add`, or stop managing it with `agentx skill remove`, as the error says.

`skill place` changes nothing, with or without `--force`, when symlinks make what it would change overlap something it must leave alone. It stops with exit code 6 and names the paths when:

- it would remove a displaced directory while the skill's own library directory, for example `~/.agents/skills/pdf`, is a symlink. agentx installs every skill as a real directory, so replace the link with the directory it leads to.
- a client's directory it would replace or create lies inside your library, holds it, or overlaps a directory a library entry links to. For example, `~/.cursor/skills` is a link to `~/.agents/skills/docx`, or `~/.agents/skills/docx` is a link to `~/.claude/skills/pdf/docx`.
- one client's directory lies inside another's, for example `~/.cursor/skills` is a link to `~/.claude/skills/pdf/sub`: replacing `~/.claude/skills/pdf` would take everything in Cursor's skills directory with it.
- it would remove a displaced directory while the skill's library directory holds a symlink. agentx never installs one there, so it is your edit: see it with [`agentx skill diff`](#see-what-you-changed) and [get the original back](#get-the-original-back), or replace the link with the files it leads to. A run that only writes placements is not affected.

```text
error: /home/me/.cursor/skills/pdf lies inside /home/me/.claude/skills/pdf, and placing one would change the other, so nothing was placed
hint: replace the symlink that joins them with the files it leads to, or move one of them elsewhere, then run 'agentx skill place pdf' again
```

Keep the two apart, then run the command again. A client's skills directory that is a link to a folder of yours outside the library, such as a dotfiles folder, is fine: agentx follows it there. agentx does not search your disk for other links: a link of yours into a directory you discard with `--force` leads nowhere afterwards.

## Check for updates

Look for newer versions of the skills you installed, including the ones you forked:

```sh
agentx skill check-updates
```

```text
✓ checked 3 skills from 2 sources: 1 update available
  pdf  update available  3f2a9c1 -> 8b1e0f4  2 files
    modified  SKILL.md
    added     forms.md
Apply an update with agentx skill update <name>, or read it first with agentx skill diff <name> --update.
```

agentx fetches every source your managed skills came from, and the upstream of every skill you forked, once each and a few at a time, with your own git, so the credential helper, SSH key and URL rewrites you use in a terminal apply. It then compares each skill with what its source holds now and lists every skill that has a newer version, with the files that version changes. Paths are relative to the skill's directory. A forked skill is compared by the upstream version it was last forked or updated from, not by your own commits: see [Take a new upstream version](/cli/fork#take-a-new-upstream-version).

Nothing is applied. Your library, your clients and your edits stay exactly as they were. agentx records the newer upstream version it found so that you can read it, apply it with [`agentx skill update`](#update-a-skill), and so that `agentx skill list` shows `update available` for the skill:

```text
1 skill
  pdf  managed  current, update available  https://github.com/anthropics/skills/skills/pdf  4 placements
```

Run the check again whenever you like. It lists every update available, including the ones an earlier check found. The exception is a skill it could not check this time: the check names it in a warning, and `agentx skill list` still shows that skill's update.

A newer version upstream replaces the one found before. A change that does not reach your library, such as a symlink in the source, which agentx never installs, is not an update. If a newer version gives the skill another name, the check says so; the skill keeps the name you installed it under.

With an account remote set, the check also fetches it and lists each of your own skills placed on this machine that another machine published changes to. Take those changes in with `agentx skill update <name>`:

```text
  notes  published from another machine  4c2d1e9 -> 7a0b3f2  1 file
    modified  notes.md
```

What another machine published is not recorded, so `agentx skill list` does not show it and `agentx skill diff --update` cannot read it: run the check again to see it, or `agentx skill update <name>` to take it in. If the account remote cannot be reached, the check warns, still checks your other sources, and exits with code 3.

The [desktop app's background process](/cli/serve#update-checks) runs the same check when it starts and every thirty minutes, and fetches every other source you added in the same pass.

### Read an update

Show what an update changes, file by file:

```sh
agentx skill diff pdf --update
```

```text
the update of pdf at 8b1e0f4 differs from its base version at 3f2a9c1 in 2 files
diff --git a/SKILL.md b/SKILL.md
...
```

The diff compares the version you installed with the version the last check found. It leaves out your own edits, which `agentx skill diff pdf` shows, and it needs no network. If no check has found an update for the skill, the command stops with exit code 6 and tells you to run `agentx skill check-updates`.

### A skill its source no longer holds

If a skill's directory is deleted from its source, or loses its `SKILL.md`, the check says so:

```text
✓ checked 3 skills from 2 sources: no update available, 1 upstream removed
  docx  upstream removed  https://github.com/me/skills/docx at 8b1e0f4
```

The skill stays in your library as it is, shows `upstream removed` in `agentx skill list` and is never updated. If the source brings it back, the next check clears the state.

### When a source cannot be reached

A source that cannot be fetched is one warning that names it, the reason and the skills it left unchecked:

```text
warning: https://github.com/me/skills: git fetch: fatal: could not read from remote repository; not checked: docx
```

The check goes on with every other source and records what it finds, then exits with the code for that failure, `3` for a source it cannot reach. Updates found earlier for the skills of that source are kept.

### Sources you removed

The check skips the skills of a source you removed with `agentx source remove`: it does not fetch the source and keeps what an earlier check found for them. Add the source again to check them.

## Update a skill

Apply the update a check found:

```sh
agentx skill update pdf
```

```text
✓ updated pdf from 3f2a9c1 to 8b1e0f4, 1 copy placement refreshed
```

agentx replaces the skill's library directory with the newer version and records it as the version you have. Every client that links to the library sees the new version at once. `agentx skill list` shows the skill as `current` again, and its `update available` is gone.

The update of a skill installed from a shared source needs no network: it applies exactly the version the last check found, the one `agentx skill diff pdf --update` shows. agentx never updates a skill unless you run this command. A skill you edited keeps your edits; see [A skill you edited](#a-skill-you-edited).

Files your ignore rules name stay: a `.DS_Store`, an editor's backup file or an ignored `build` folder (see [Files that do not count](#files-that-do-not-count)). If the newer version ships a file at the same path, its file replaces yours.

Update every skill that has an update:

```sh
agentx skill update --all
```

```text
✓ updated 2 skills, 1 edited skill merged cleanly, 1 copy placement refreshed
  pdf   3f2a9c1 -> 8b1e0f4  1 copy placement refreshed
  xlsx  5d6e7f8 -> 9a0b1c2  edits merged cleanly
```

If no check has found an update for the skill, the command says it is up to date as of the last check and changes nothing. Run `agentx skill check-updates` to look again.

A copy placement is handled on its own:

- A copy that holds the version you are replacing gets the new version, and keeps the files your ignore rules name in it.
- A copy you edited in place is kept exactly as it is and skipped, with the warning for a [copy that differs from the library](#a-copy-that-differs-from-the-library).
- A copy agentx cannot read is kept as it is and skipped, with a warning that says why.

If a newer version gives the skill another name, the skill keeps the name you installed it under, and the update says so.

Only what the skill held when you ran the command is replaced:

- If the skill changes before the update starts to write, for example because your editor saves a file or a check finds another version, agentx stops with exit code 6 and changes nothing. Run the command again.
- If a file of the skill changes while the update is being written, agentx stops with exit code 6, keeps your change and says that recovery is required. Restore the file it names to let the next command finish the update. To keep your change instead, move the named file in `~/.agentx/mutations` aside; the skill then shows as modified against the new version, with no update available.

agentx keeps what it replaces until the update is complete, so an interrupted update finishes on the next command, running the update again included, and loses nothing.

### Take in what another machine published

Your own skills travel between your machines through the [account remote](/cli/source#add-your-account-remote): the ones you created with `agentx skill new`, forked with `agentx skill fork`, or installed from the account remote. Take in what you published of them from another machine the way you take an update:

```sh
agentx skill check-updates
agentx skill update --all
```

```text
✓ took in notes from the account remote: fast-forward to 4c2d1e9
no skill was updated from upstream
```

- `agentx skill check-updates` lists what the account remote holds that this machine lacks as `published from another machine`. Checking first is optional: `agentx skill update <name>` fetches the account remote itself.
- `agentx skill update <name>` takes in what the account remote holds of one skill. `agentx skill update --all` does so for every one of your own skills on this machine.
- When this machine has no commits of its own, the skill moves to the published commit: a fast-forward, with nothing new committed. When both machines committed, agentx merges the two with Git and commits the merge, as `notes: merge the account remote (desktop)`.
- A skill you forked from a source takes in what the account remote holds first, then its new upstream version, as two commits.
- Edits you have not published are recorded on the skill first, and what the account remote holds is merged with them. They stay unpublished until you [publish](#publish-a-skill) them. Publish with `-m` to publish them under your own message.
- Take them in before you publish: [`agentx skill publish`](#publish-a-skill) never merges, and stops with exit code 6 when another machine published changes and this machine has changes of its own.
- When both machines changed the same lines, the merge waits for you: see [Resolve a conflict](/cli/fork#resolve-a-conflict). Resolve it, then run `agentx skill update <name>` again.
- A skill with no upstream (one you created with `agentx skill new`, or forked from an unmanaged or a plugin's skill) that has nothing new on the account remote is `up to date with the account remote`. One you never published has no branch there yet, and the update tells you to run `agentx skill publish <name>`. One another machine removed from the account remote, or renamed there, gets a warning naming the two ways on: remove it here, or publish it again.
- If Git cannot reach the account remote, the update of a skill with no upstream stops with exit code 3; a skill you forked from a source gets a warning and still takes its new upstream version.

A forked skill remembers the upstream version it was last updated from. When both machines took different versions of the same upstream, the merge records the newer one, but only when the source's history on this machine proves it newer: run [`agentx source fetch`](/cli/source) first to fetch that history. Otherwise the merge keeps this machine's version, and at worst the next update conflicts where both versions changed the same lines. When the merge brings a newer upstream version than the update your last check found, agentx drops that update, so the update never takes the skill back to the older version.

### A skill you edited

A skill you changed since you installed it keeps your changes: agentx merges them into the newer version, the way git merges two branches, with the version you installed as their common base. When your changes and the update change different lines, the merge is clean and the update applies at once:

```text
✓ updated docx from 3f2a9c1 to 8b1e0f4 and merged its edits cleanly
```

The skill is then at the new version with your changes on top of it, so `agentx skill list` still shows it as `modified`, and `agentx skill diff docx` shows your changes against the new version. Every change counts, whatever tool made it, except files your ignore rules name: they are not part of your edits and are kept as for any update. A file you added inside a folder the update renamed stays where you put it. Copies are handled as for any update: a copy that still held the version you installed, or your edited version, gets the merged one.

Git merges line by line, and changes to lines next to each other conflict, so a short file conflicts more often than you might expect. Read the update with `agentx skill diff docx --update` before you apply it.

### When your edits conflict

When your changes and the update change the same lines, agentx changes nothing in your library. The merge waits in a Git worktree of the account repo in agentx home, `~/.agentx/merges/<name>`, never in the directory your agents read. So an agent never loads a half-merged file with conflict markers in it, and the skill keeps working exactly as you left it.

`skill update` stops with exit code 4 and lists the files that conflict, each with what `git status` says of it:

```text
docx conflicts with its update from 3f2a9c1 to 8b1e0f4 in 2 files
SKILL.md: both modified
logo.png: both modified
error: docx conflicts with its update in 2 files, so the merge is pending and the library directory was left as it is
hint: resolve it with git in /Users/you/.agentx/merges/docx/docx ('git add' each file you resolved, or 'git checkout --ours|--theirs <file>' then 'git add'; 'git commit' is optional), then run 'agentx skill update docx' again to apply it, or 'agentx skill update docx --abort' to give it up
```

As in `git status`, "us" is your library directory and "them" the update: a file you deleted and the update changed reads `deleted by us`, and one the update added where you had added a file too reads `both added`. Files your ignore rules name are not part of your edits, so they never conflict and stay as they are.

The worktree holds a Git merge in progress like any other: your edits are checked out and the update is being merged into them. It holds the skill one folder down, and the hint names that folder, so the files listed are found there by the paths shown. Conflict markers are longer than any line of the skill that looks like one, such as a `=======` rule, so you can tell them apart. The merge stays until you finish it or give it up, across restarts, and `agentx skill list` shows the skill as `merge pending`. Meanwhile:

- `skill fork`, and `skill remove` without `--from` or with `--from universal`, stop with exit code 4 and change nothing.
- Everything else works as usual: placing the skill, `skill place --force` included, removing it from one client, `skill diff`, and update checks, which may find a newer version still.

With `--all`, a skill whose edits conflict is left with its merge pending and the other skills are still updated. The run then exits with code 4, or 6 if other skills were not updated for other reasons.

### Finish the merge

Resolve the merge with Git in the folder the hint names:

```sh
cd ~/.agentx/merges/docx/docx
git checkout --theirs logo.png   # take the update's version of a file whole, or --ours for yours
git add logo.png
```

Edit a file that conflicts to keep what you want from both sides, then `git add` it. `git status`, `git diff` and `git commit` work there as in any merge; committing is optional. Then run the update again:

```sh
agentx skill update docx
```

```text
✓ updated docx from 3f2a9c1 to 8b1e0f4 with the merge you resolved
```

agentx applies the merge as it applies a clean one: your library directory takes the merged files, copies are refreshed, and the worktree is removed, so leave it with `cd` if your shell is still in it.

- Only what you `git add`ed is applied, as `git commit` would record it. A change you made after `git add`, or a new file you never added, is removed with the worktree.
- It applies the version the merge started with, even if a check has found a newer one since; that newer one stays as the skill's next update.
- `agentx skill update --all` applies it too, with the other updates.
- Until every file is resolved, the update lists the files that are left and stops with exit code 4 again, changing nothing.

The update does not apply the merge, and stops with exit code 6, if the skill's library directory changed while the merge was pending, or if something outside agentx moved the skill's record in the account repo. Give the merge up and update again.

### Give the merge up

```sh
agentx skill update docx --abort
```

```text
✓ gave up the merge of docx; the library directory is as it was
```

This removes the worktree and whatever you resolved in it. Your library directory, its placements and the update agentx found are left exactly as they were, so `agentx skill update docx` merges again from scratch.

### When a skill is not updated

- A skill with a [merge pending](#when-your-edits-conflict) that still has files to resolve stops with exit code 4 and lists them.
- `agentx skill update <name>` of a skill whose source you removed stops with exit code 5, and the hint names the `agentx source add` command that brings the source back. With `--all`, the skill is skipped with a warning that names the same command, and the run does not fail. Either way, the update found earlier is kept.
- A skill its source no longer holds, shown as `upstream removed`, is kept as it is and never updated: exit code 6.
- A skill agentx did not install has no update to apply: exit code 6. One of your own skills is updated by merging, see [Take a new upstream version](/cli/fork#take-a-new-upstream-version); one with no upstream, such as a skill you created, stops with exit code 6 when no account remote is set. With one set, its update takes in what your other machines published, see [Take in what another machine published](#take-in-what-another-machine-published).
- A skill whose library directory is gone stops with exit code 6. Install it again with `agentx skill add <source> --name <name>`, or stop managing it with `agentx skill remove <name>`.
- A skill whose record in the account repo agentx cannot read stops with exit code 6. Run `agentx doctor` and check the account repo it names.
- A skill whose library directory is a symlink to a directory of your own stops with exit code 6, even if you edited that directory: an update replaces the library directory, so it would remove your link. Replace the link with the directory it points to, then update again. With `--all` this skill is counted as not updated.
- A skill that holds something git cannot record, such as a repository nested in it, stops with exit code 6 and names it: an update would discard it with no record of it anywhere. Move it out of the skill, then update again. With `--all` this skill is counted as not updated.

With `--all`, a skill that is not updated does not stop the others: agentx names it and still updates the rest, then exits with the code those skills share, or 6 when they differ. A skill whose source you removed is skipped rather than counted, so it leaves the exit code at 0.

## Publish a skill

Publish one of your own skills, one you created with `agentx skill new` or forked with `agentx skill fork`, to your [account remote](/cli/source#add-your-account-remote) so your other machines can install it and take in what you change:

```sh
agentx skill publish release-notes -m "Cover reverted pull requests"
```

```text
✓ published release-notes as 4c2e9a1
```

- Your edits stay on this machine until you publish them. Publishing records them as one commit on the skill's history, then pushes it. There is no separate commit step.
- Give the commit a message with `-m`. Its first line is the subject. Without `-m`, agentx writes one that names the skill, the files you changed and this machine, such as `release-notes: edit SKILL.md (laptop)`.
- With `-m`, edits that [`agentx skill update`](#take-in-what-another-machine-published) recorded on the skill, what it merged from another machine, and commits you made with Git in the skill's worktree are published in the same one commit, under your message. A [rename](/cli/fork#rename-a-skill-of-your-own) or an update from upstream that you have not published yet keeps its own commit: agentx then warns that `-m` was not used, unless the skill also has new edits, which get your message.
- Run `agentx skill publish` with no name to publish every skill of your own. `-m` then gives the message of each commit it records. A bare publish never covers a skill you installed from a shared source: name it to [publish it to its source](#publish-edits-to-a-shared-source). It also leaves out a skill another machine removed from the account remote or renamed there, shown as `remote removed`, with a warning: name it to publish it again.
- [Files that stay local](/cli/fork#files-that-stay-local), such as a `.DS_Store`, are never published.
- Each skill goes to its own branch, `skills/<name>`. Publishing one skill leaves your other skills where they are.
- When another machine published changes to the skill first, publishing stops with exit code 6 and records nothing: your edits stay where they are. Run [`agentx skill update <name>`](#take-in-what-another-machine-published) to take them in, then publish again. A skill with no edits and nothing new of its own has nothing to publish: agentx warns, and the publish still succeeds.
- agentx never forces a push. When another machine published meanwhile, the push stops the same way: run `agentx skill update <name>`, then publish again. Edits recorded before a failed push go out with your next publish.
- When the remote's host declines the push, for example a hook or a protected branch, publishing stops with exit code 6 and names the host's reason, with up to three lines the host wrote:

  ```text
  error: the account remote declined skills/release-notes: pre-receive hook declined: no pushes on Fridays
  hint: agentx never forces a push; once the account remote takes it, run 'agentx skill publish release-notes' again
  ```

  There is nothing to update: fix what the host says, then publish again.
- When the remote does not let this machine push, publishing stops with exit code 3. The hint says what to fix:
  - Credentials that only allow reading, or none: check the git credential helper or SSH key you use for the remote.
  - A host SSH does not trust yet: connect to it once with `ssh` to add its key to `known_hosts`.
  - An organisation that requires single sign-on or an IP allow list: authorise your token or key for the organisation, or allow this machine's IP address.
- Nothing is published for you. Run `agentx skill publish` each time you want your changes on the remote.
- Publishing needs an [account remote](/cli/source#add-your-account-remote). Without one, it stops with exit code 6 and names `agentx source add <url> --account`.
- When no skill has edits to record, agentx warns that `-m` was not used.
- A skill agentx does not manage has no source to publish to: fork it with `agentx skill fork <name>` to make it one of your own.
- To delete a skill's branch from the remote, remove the skill with [`agentx skill remove <name> --remote`](/cli/fork#remove-a-skill-of-your-own).

### Publish edits to a shared source

Push the edits of a skill you installed from a shared source back to that source, for example a fix to a skill of your team's repository:

```sh
agentx skill publish pdf -m "Keep the original file"
```

```text
✓ published pdf to main of https://github.com/acme/skills as 9b1d7e3
```

- Name the skill. A bare `agentx skill publish` never pushes to a shared source.
- No account remote is needed. Publishing to a shared source never reads or fetches yours.
- agentx writes one commit on the branch the skill is installed from: the source's default branch, or the branch you pinned it to. The commit changes the skill's folder alone, and everything else on the branch stays as it is.
- The commit carries your own Git identity. Set it first with `git config --global user.name "Your Name"` and `git config --global user.email you@example.com`: without it, publishing stops with exit code 6. The commit carries no agentx data.
- Give the commit a message with `-m`. Without `-m`, the message is `Update <folder>`, such as `Update skills/pdf`, or `Update <directory name>` for a skill at the root of its repository.
- Afterwards the skill stays managed and shows as `current`: the version you published is the one it compares with.
- A skill with no edits has nothing to publish. agentx says so without fetching anything.
- When the source changed the skill since you installed it, publishing stops with exit code 6 and pushes nothing. Your edits stay where they are. Take the change in with [`agentx skill update <name>`](#update-a-skill), then publish again:

  ```text
  error: https://github.com/acme/skills changed pdf since it was installed, so it was not published
  hint: run 'agentx skill update pdf' to take the change in, then publish again
  ```

- When someone pushes to the branch between agentx's fetch and its push, agentx fetches the source again and checks once more. A change to other folders is no obstacle: the commit goes on top of it. A change to the skill stops the publish as above, and `agentx skill update <name>` then takes it in.

- While a merge with an update is pending, publishing stops with exit code 4: [finish the merge](#finish-the-merge) or give it up first.
- When you removed the skill's source from this machine, publishing stops with exit code 5: add it again with `agentx source add <url>`.
- When the source's host declines the push, for example a hook or a protected branch, publishing stops with exit code 6 and names the host's reason. Fix what the host says, then publish again.
- When the source does not let this machine push, publishing stops with exit code 3. Check the git credential helper or SSH key you use for it, as for [your account remote](#publish-a-skill).
- A skill installed from a tag or a commit has no branch to publish to: publishing stops with exit code 6. Add the source at a branch with `agentx source add <url>#<branch>`, update the skill, then publish again.
- A symlink you add to the skill is never pushed: publishing stops with exit code 6. Replace it with the file it leads to, or remove it.
- When the skill holds a file agentx would not install, or something Git cannot record, publishing stops with exit code 6. Move it out of the skill, then publish again.
- When the source no longer holds the skill, publishing stops with exit code 6. Run `agentx skill check-updates` once the source holds it again, or remove the skill.
- When the skill changes while it is being published, for example an update takes a new version in, publishing stops with exit code 6. Publish again.
- When the push ends without saying whether the source took it, publishing stops with exit code 3. Publish again: if the source took it, that finishes the publish.
- When the source took the commit but agentx could not record it, because another command held agentx home or changed the skill meanwhile, the publish still succeeds with a warning. Follow its hint: publish again, or check for updates and update the skill.

### Two skills with one name

Every skill of your own has a permanent id. A skill you create on two machines under the same name is two skills, with two ids. agentx never mixes them: once one is published, publishing or updating the other stops with exit code 6:

```text
error: the account remote's skills/release-notes is a different skill than release-notes on this machine, so release-notes cannot be published
hint: rename yours with 'agentx skill rename release-notes <new>', then publish that one
```

[Rename](/cli/fork#rename-a-skill-of-your-own) yours, then publish it under its new name. Publishing the renamed skill never deletes the other skill's branch, since it has another id. A remote branch whose history records no id stops the same way, since nothing tells that it holds the same skill.

## Where it is recorded

The account repo is a Git repository in agentx home, `~/.agentx/account.git`, that plain `git` can read. Every install writes one commit per skill in it: the version's files, the source it came from, the last upstream commit that changed the skill and its content hash. That commit is the same on every machine that installs the same version, however recently each one fetched the source, so your machines agree on what "the version you have" means without sending anything anywhere. A skill installed on its own and the same skill installed as part of a bulk install get the same commit.

## Exit codes

- `1`: a usage error:
  - the command line names no skill to install;
  - the flags contradict each other: `--all` with `--name`, `--except` without `--all`, `--except` leaving nothing, or `--from universal` with a client that is not universal;
  - it names the source with another branch or tag than its pin;
  - `skill add` is given something that is not a source, for example the name of a skill the library already holds;
  - `skill add` with no source is given neither `--name` nor `--all`, or is given `--fetch`;
  - `skill update` was given both a name and `--all`, neither, or `--abort` with `--all`;
  - `skill publish` was given an empty `-m`, or an `-m` that ends in a trailer agentx writes itself.
- `3`: the source, or the files of the skill, could not be fetched. For `skill check-updates`, also a run whose sources and skills failed for different reasons. For `skill update`, also the account remote, for a skill with no upstream. For `skill add` with no source and `skill publish`, the account remote, and for `skill publish` also a remote that does not let this machine push, and the shared source of a skill you publish to it.
- `4`: `skill update` found your edits, or what another machine published, conflicting with the update and left the merge pending, or found files of a pending merge still to resolve, or a merge already pending blocks `skill fork`, `skill publish` of a skill of a shared source, a `skill remove` that takes the skill off the machine, or a `skill add` from the account remote over a managed skill of that name. See [When your edits conflict](#when-your-edits-conflict).
- `5`: something the command names does not exist:
  - a source id names no source on this machine (for a source you removed, the hint names the `agentx source add` command that brings it back), the source did not serve a skill's files, the path or a skill named by `--name` or `--except` does not exist in the source, or `--to` or `--from` names a configuration that is not detected;
  - `skill place`, `skill diff` and `skill update` (except with `--abort`): also a name the library does not hold as a skill, other than one of your own skills for `skill place`, which [puts it back](/cli/fork#recover-a-skill-of-your-own);
  - `skill update`: also a skill whose source you removed;
  - `skill remove`: a name that is neither a skill of the library nor a managed skill whose library directory is gone;
  - `skill publish`: also a name that is neither in the library nor one of your own skills on this machine; when your account remote holds it, the hint names `agentx skill add --name <name>`. Also a skill whose shared source you removed from this machine.
  - `skill check-updates`: also a source added on this machine that it has never fetched, such as one `agentx import` brought back; `agentx source add` fetches it.
  - `skill add` with no source: also a name `--name` gives that the account remote holds no skill of, an `--except` name that is not one of the skills the account remote holds that this machine lacks, or a skill on the account remote with no `SKILL.md`.
- `6`: agentx refused:
  - the library already holds a different skill under that name, the name is already managed at another version, the skill's name cannot be both a directory and a git branch, the skill's directory in the source is not one agentx can record, the skill holds a file whose path would put it outside the skill's directory, agentx cannot use your library directory, or an interrupted change has to be resolved before anything else can run. The message names what to restore; if you would rather keep what is there, move the named file in `~/.agentx/mutations` aside.
  - `skill add` with no source: also no account remote set; a name agentx cannot use for a skill; a skill already installed on this machine; a library that holds a symlink, a file, edits or a folder of its own at the skill's name; a managed skill of that name whose library directory is gone; a folder already at the skill's worktree path; or a branch on the account remote whose history records no fork id.
  - `skill remove`: also `--from` naming a universal client, one that reads the library directly, even next to `--from universal`; `--from <client>` for a skill whose library directory is gone; `--remote` for a skill that is not your own, one of another source or with no source; and, for one of your own skills, see [Your own skills](/cli/fork#exit-codes).
  - `skill diff`: a skill agentx did not install, which has no base version, or a managed skill whose import branch records no version agentx can read. For one of your own skills, see [Your own skills](/cli/fork#exit-codes).
  - `skill diff --update`: also a skill no check has found an update for.
  - `skill check-updates`: a newer version agentx will not install, for the reasons `skill add` refuses one.
  - `skill place`: a displaced directory that differs from the library when `--force` is not given; for one of your own skills, see [Your own skills](/cli/fork#exit-codes); a managed skill whose library directory is gone; a skill or placement that changed while it was being placed; a library directory that is a symlink or holds one when the command would remove a displaced directory; and a client's directory it would change that symlinks make overlap the library, a directory a library entry links to or another client's directory.
  - `skill update`: a skill agentx did not install, a managed skill whose library directory is gone or whose import branch records no version agentx can read, a skill its source no longer holds, a skill that holds something git cannot record, a skill whose library directory is a symlink, or a skill, its installed version or its update that changed while it was being updated. With a merge pending, also a library directory edited or a record moved outside agentx while the merge was pending; see [Finish the merge](#finish-the-merge).
  - `skill update --abort`: any name with no merge pending, one the library does not hold included.
  - `skill publish`: no account remote set; a skill agentx does not manage; for a skill of a shared source, see [Publish edits to a shared source](#publish-edits-to-a-shared-source); another machine published changes the skill lacks while this machine has changes of its own; the remote's branch of that name is [another skill](#two-skills-with-one-name); the skill's worktree is missing, needs repair or is not on its branch, waits for a Git command you ran there to finish, or Git is running there (see [Recover a skill of your own](/cli/fork#recover-a-skill-of-your-own)); its skill folder is missing; it holds a Git repository its `.gitignore` does not cover; the skill changed while its edits were being recorded; or the remote's host declined the push.
  - A run of several skills, other than `skill check-updates`: the skills that were skipped disagree about why. A run whose failures all have one cause exits with that cause, so a batch that skipped two skills the source did not serve exits `5`.
- `7`: another agentx command is running. Retry when it finishes.
- `8`: the account repo in agentx home cannot be read or written. Run `agentx doctor`. For `skill update`, also an update that holds the skill in another folder than the version you have; run `agentx skill check-updates` to record it again.
- `10`: agentx could not read its own settings file, the library still held the skill after `skill remove` took it away, or agentx hit an error it has no better answer for. Run `agentx doctor`.
