---
title: "agentx skill"
description: "Install, place, update, publish and remove skills, and see what is in your library."
---

Your library is one directory, `~/.agents/skills`, that holds every skill agentx manages. agentx installs a skill there once and links it into each agent client. Every client sees the same files, and one update reaches all of them. This page uses the terms placement, universal client, configuration, managed skill and base version; see [Key terms](/#key-terms).

## Install a skill

```sh
agentx skill add anthropics/skills --name pdf
```

```text
✓ added https://github.com/anthropics/skills at 8c41d07: 17 skills; write access unknown
✓ installed pdf from https://github.com/anthropics/skills under skills/pdf at 3f2a9c1, source fetched 2026-09-22T10:00:00Z: 4 placements
  claude-code  symlink  /home/me/.claude/skills/pdf -> /home/me/.agents/skills/pdf
  codex        library  /home/me/.agents/skills/pdf
  cursor       symlink  /home/me/.cursor/skills/pdf -> /home/me/.agents/skills/pdf
  gemini-cli   library  /home/me/.agents/skills/pdf
  always available to universal clients: codex, gemini-cli
```

Each row is one client's placement. For a universal client, the placement is the library entry itself. See [Clients that see every skill](#clients-that-see-every-skill).

If you have not added the source yet, `skill add` adds it first, as [`agentx source add`](/cli/source) does. The source stays added even if the install fails. Name a new source by its URL or as `owner/repo`. A source id works only for a source you already added.

For a source you already added, agentx installs from its last fetch, and the output shows when that was (`source fetched ...`). To install the latest version, add `--fetch`, or run `agentx source fetch` first:

```sh
agentx skill add anthropics/skills --name pdf --fetch
```

A source follows one branch, tag or commit, its [pin](/cli/source#pin-a-source). To install from another ref, change the pin first with `agentx source add <url>#<ref>`. If you give `skill add` a different ref, it stops with exit code 1.

When the source holds more than one skill, name the one you want with `--name`. `--name` and `--except` match the `name` in the skill's `SKILL.md`, or the directory name if there is no `name`. Case does not matter. If the path points at one skill, leave `--name` out:

```sh
agentx skill add anthropics/skills/skills/pdf
```

### Install several at once

Give `--name` once for each skill you want:

```sh
agentx skill add anthropics/skills --name pdf --name xlsx --name docx
```

Or take the whole source and leave out what you do not want:

```sh
agentx skill add anthropics/skills --all --except artifacts-builder
```

You cannot use `--all` with `--name`, and `--except` works only with `--all`. `--all` also works with a source you have not added yet.

If one skill cannot be installed, the rest still land. agentx names the one it skipped and why, and exits non-zero:

```text
warning: xlsx: the library already holds xlsx at /home/me/.agents/skills
✓ installed pdf from https://github.com/anthropics/skills under skills/pdf at 3f2a9c1, source fetched 2026-09-22T10:00:00Z: 4 placements
  ...
error: 1 of 3 skills could not be installed: xlsx: the library already holds xlsx at /home/me/.agents/skills
hint: remove /home/me/.agents/skills/xlsx and install again, or keep it under another name: fork it with 'agentx skill fork xlsx --name <new>', remove it with 'agentx skill remove xlsx', then install again
```

To keep the skill that holds the name, fork it under a new name, remove it, then install again. The fork alone leaves the skill in place, so the name stays taken until you remove it:

```sh
agentx skill fork xlsx --name my-xlsx
agentx skill remove xlsx
agentx skill add anthropics/skills --name xlsx
```

If the skill that holds the name is one of your own skills, [rename it](/cli/fork#rename-a-skill-of-your-own) instead with `agentx skill rename xlsx my-xlsx`, then install again. Removing only its folder is not enough, because agentx still keeps your skill under that name.

agentx also refuses a skill whose directory name in the source holds a control character, or starts or ends with a space. Ask the source to rename the directory, or install another skill.

### Clients that see every skill

Some clients, such as Codex and Gemini CLI, read the library directly. These are universal clients. They see every skill in the library, so they get no link of their own. A client also becomes universal when its skills directory and the library are one directory through a symlink. For example, if `~/.claude/skills` is a symlink to the library, Claude Code reads the library, and so does Cursor, which also reads `~/.claude/skills`.

Every other client gets a symlink in its own skills directory, pointing at the library.

A universal client sees every skill in your library, even if you disabled that client with `agentx config disable` or left it out of `--to`. The install output ends with a line that names them:

```text
  always available to universal clients: codex, gemini-cli
```

The line is left out when no universal client is installed. To take a skill away from the universal clients, remove it from the library. See [Clients that read the library](#clients-that-read-the-library).

### Choose where it goes

By default a skill is placed in every enabled configuration. To choose, name the configurations with `--to`:

```sh
agentx skill add anthropics/skills --name pdf --to claude-code --to cursor
```

`--to` names the configurations for this install, in place of every enabled one. You can name a configuration you disabled. Universal clients see the skill whatever `--to` names.

### Copy instead of link

```sh
agentx skill add anthropics/skills --name pdf --copy
```

Use `--copy` for a client that cannot follow a symlink. agentx remembers the choice. Later installs and placements give that client a copy without `--copy`.

### If something is already there

| What is at the path | What agentx does |
|---|---|
| Library: this exact version | Records it as managed. Changes nothing on disk. |
| Library: other content | Stops that skill with exit code 6. Move or remove the directory, then install again. In a run of several skills, agentx still installs the others. |
| Placement: a symlink to the library | Leaves it. |
| Placement: a directory with this exact version | Replaces it with a symlink and reports it as adopted. |
| Placement: a copy agentx placed that you changed | Keeps it and warns. See [A copy that differs from the library](#a-copy-that-differs-from-the-library). |
| Placement: your own symlink or anything else | Leaves it and warns. |
| A skills directory agentx cannot write | Skips it and warns. |

An install never overwrites your files.

agentx installs only regular files and directories. It leaves out a symlink or a git submodule inside a skill and warns about each one.

### A copy that differs from the library

A copy agentx placed stops matching the library when you edit the copy or when the skill in the library changes. `agentx skill place` and `agentx config enable --place-all` keep that copy exactly as it is and skip it, with a warning:

```text
warning: cursor's copy of pdf is different from the library, so it was left unchanged (/home/me/.cursor/skills/pdf)
  to replace it with the library version: agentx skill remove pdf --from cursor && agentx skill place pdf --to cursor --copy
```

To replace the copy with the library version, run the command on the second line of the warning. This deletes what the copy holds, so save what you want to keep first.

### Install your skills on another machine

Your own skills, the ones you create or fork and then publish to your [account remote](/cli/source#add-your-account-remote), install on another machine from that remote. Add the same remote there with `agentx source add <url> --account`, then list the skills it holds that this machine has not installed:

```sh
agentx skill list --remote
```

```text
1 skill
  pdf  managed  current  https://github.com/anthropics/skills/skills/pdf  4 placements
2 installable skills on the account remote
  release-notes  managed  installable  ssh://git@github.com/you/forks (account)
  standup        managed  installable  ssh://git@github.com/you/forks (account)
Install one with agentx skill add --name <name>, or all of them with agentx skill add --all.
```

- `--remote` fetches the remote first. A remote Git cannot reach stops with exit code 3.
- Each `installable` row shows the skill's source column as `agentx skill list` does. See [List your skills](#list-your-skills).
- A branch on the remote that agentx cannot install is left out with a warning: one whose name is not a valid skill name, or whose history records no fork id.

Run `agentx skill add` with no source to install from the account remote. Name a skill with `--name`, once for each:

```sh
agentx skill add --name release-notes
```

```text
✓ installed release-notes from the account remote at 4c2e9a1: 1 placement
  claude-code  symlink  /home/me/.claude/skills/release-notes -> /home/me/.agents/skills/release-notes
```

Or install every skill the account remote holds that this machine lacks, and leave out what you do not want with `--except`:

```sh
agentx skill add --all --except standup
```

- It is the same skill, with its history. Publish your edits here, and they go to the same branch.
- agentx fetches the account remote every time, so leave out `--fetch`: with no source it stops with exit code 1. `--name` and `--except` match the name exactly. `--to` and `--copy` work as for a source.
- If you forked the skill from a source this machine has not added, agentx adds that source, so [`agentx skill check-updates`](#check-for-updates) finds its updates.

#### When the library already holds the name

- **The same skill installed from its source, without edits**: the skill from the account remote replaces it. Symlink placements lead to the new skill. A copy placement keeps the old version until you run `agentx skill place <name>`.
- **A managed skill with an update merge pending**: agentx stops with exit code 4. Finish the merge, or give it up with `agentx skill update <name> --abort`, then install again.
- **A managed copy with your edits, or any other folder**: agentx stops with exit code 6 and changes nothing. Move the folder aside, or remove the skill with `agentx skill remove <name>`, then install again.
- **A symlink**: agentx stops with exit code 6. Remove the link, then install again.

## Place a skill

`agentx skill place` puts a skill the library already holds into more clients, and puts back the placements `agentx skill list` flags.

### Place a skill you already have

Put a skill the library already holds into another client:

```sh
agentx skill place pdf --to cursor
```

```text
✓ placed pdf in 1 configuration
  cursor  symlink  /home/me/.cursor/skills/pdf -> /home/me/.agents/skills/pdf
  always available to universal clients: codex, gemini-cli
```

The first line counts the configurations you placed the skill in, and any placements agentx skipped. Each client you named gets one row. A client whose placement was skipped gets a row only if it sees the skill through another client's skills directory, as Cursor reads Claude Code's.

Name each client with `--to`, once for each. Without `--to`, agentx places the skill into every enabled client and puts back what `agentx skill list` flags there; see [Put back placements](#put-back-placements). Add `--copy` for a client that cannot follow a symlink; agentx remembers the choice, as it does for `agentx skill add --copy`. To turn a recorded copy back into a symlink, take it away with `agentx skill remove pdf --from cursor`, then place the skill again with `agentx skill place pdf --to cursor`.

What is already at the path decides what happens, as for an install (see [If something is already there](#if-something-is-already-there)), with one difference: a directory that holds other content stops the command, unless you add `--force`. See [When the directory differs from the library](#when-the-directory-differs-from-the-library).

agentx lists every directory it adopted. An adopted directory becomes an agentx placement, so `agentx skill remove` deletes it later.

To place a skill that is already in your library, use `skill place`. `skill add` installs from a source. If you give it the name of a library skill, it stops with exit code 1 and shows the command to run:

```text
error: pdf is already in the library; skill add installs a skill from a source
hint: to place it in more clients, run 'agentx skill place pdf'
```

The hint keeps the `--to` and `--copy` you gave. If the argument is a source URL, `owner/repo` or a source id, `skill add` installs from that source, even if a library skill has the same name.

### Put back placements

Put back the placements `agentx skill list` shows as `missing` or `displaced`, in every enabled client:

```sh
agentx skill place pdf
```

```text
✓ placed pdf in 4 configurations
  claude-code  symlink  /home/me/.claude/skills/pdf -> /home/me/.agents/skills/pdf
  codex        library  /home/me/.agents/skills/pdf
  cursor       symlink  /home/me/.cursor/skills/pdf -> /home/me/.agents/skills/pdf
  gemini-cli   library  /home/me/.agents/skills/pdf
  adopted /home/me/.claude/skills/pdf
  always available to universal clients: codex, gemini-cli
```

- A missing placement is made again: a copy if you placed a copy there before, a link otherwise.
- A link to the library where you placed a copy is replaced with a copy.
- A real directory where the link belongs is replaced with the link when it holds exactly what the library holds, and named as adopted: nothing is lost.

Add `--to` to put back only the clients you name. agentx leaves your own links, copies you edited and disabled clients as they are.

### When the directory differs from the library

If a real directory where the link belongs holds anything else, for example because another installer copied a different version there or you edited the skill there, replacing it would delete what it holds. `skill place` stops with exit code 6 and changes nothing:

```text
error: /home/me/.claude/skills/pdf is a directory whose content differs from the library's pdf, so nothing was placed
hint: to replace it with the library's version and delete what it holds, run 'agentx skill place pdf --force'; to keep it, move it elsewhere first
```

To replace it with the library version, add `--force`. The directory is deleted and replaced with the link:

```sh
agentx skill place pdf --force
```

```text
✓ placed pdf in 4 configurations
  claude-code  symlink  /home/me/.claude/skills/pdf -> /home/me/.agents/skills/pdf
  codex        library  /home/me/.agents/skills/pdf
  cursor       symlink  /home/me/.cursor/skills/pdf -> /home/me/.agents/skills/pdf
  gemini-cli   library  /home/me/.agents/skills/pdf
  discarded what /home/me/.claude/skills/pdf held
  always available to universal clients: codex, gemini-cli
```

To keep that content, move the directory out of the client's skills directory, for example to use it as a skill of your own. Then run `skill place` again to put the link back. `--force` never changes the library.

`--force` works with `--to` and `--copy`: it replaces only the directories of the clients `--to` names, and with `--copy` the client gets a copy of the library version.

If a directory changes while `skill place` runs, agentx stops with exit code 6 and changes nothing. Run it again.

### When `skill place` stops

One of your own skills is placed as `skill add` places it. `skill place` also puts back its worktree and library symlink: see [Recover a skill of your own](/cli/fork#recover-a-skill-of-your-own). For a managed skill whose library directory is gone, `skill place` stops with exit code 6: see [A skill whose library directory is gone](#a-skill-whose-library-directory-is-gone).

`skill place` stops with exit code 6 and changes nothing when symlinks join the paths it would change, for example a client's skills directory that links into the library or into another client's directory. The error names the paths. Remove the symlink that joins them, then run the command again.

```text
error: /home/me/.cursor/skills/pdf lies inside /home/me/.claude/skills/pdf, and placing one would change the other, so nothing was placed
hint: replace the symlink that joins them with the files it leads to, or move one of them elsewhere, then run 'agentx skill place pdf' again
```

## List your skills

```sh
agentx skill list
```

```text
5 skills
  docx    managed    modified, source removed  https://github.com/me/skills/docx                                                               2 placements
  my-pdf  managed    modified                  ssh://git@github.com/you/forks (account), from https://github.com/anthropics/skills/skills/pdf  4 placements
  notes   managed    current                   ssh://git@github.com/you/forks (account)                                                        4 placements
  pdf     managed    current                   https://github.com/anthropics/skills/skills/pdf                                                 4 placements
  todo    unmanaged  -                         (none)                                                                                          2 placements
```

Each row shows the skill, its kind, whether it holds edits you have not published, its source and how many placements it has, one per client that sees it.

| Kind | What it means |
|---|---|
| `managed` | A skill agentx keeps: one installed from a source, or one of your own, which you created with [`agentx skill new`](/cli/fork#create-a-skill), forked with [`agentx skill fork`](/cli/fork#fork-a-skill) or installed from your account remote. |
| `unmanaged` | A directory in the library agentx did not install. agentx lists it and otherwise leaves it alone. |

The source column shows where the skill is published to:

- A skill of a shared source shows the source's URL and the folder in it, as `pdf` does above. Its updates come from there.
- One of your own skills shows your [account remote](/cli/source#add-your-account-remote), marked `(account)`, or `account remote not set` until you add one. A skill you forked from an installed skill also shows its upstream after `from`, as `my-pdf` does above, and takes the updates of its upstream.
- An unmanaged skill shows `(none)`.

The state column shows:

| State | What it means | What to do |
|---|---|---|
| `current` or `modified` | Whether the skill has edits you have not published. agentx compares a skill from a shared source with its base version. It compares one of your own skills with the version you last published to your account remote. Any change counts, except [files that do not count](#files-that-do-not-count). | See the changes with [`agentx skill diff`](#see-what-you-changed). |
| `displaced` | The client has the wrong kind of placement: a real directory where agentx keeps a symlink, or a symlink where you placed a copy. Another installer often causes this. | Fix it with [`agentx skill place <name>`](#put-back-placements). |
| `missing` | An enabled client has nothing of the skill in its own skills directory: you placed the skill with `--to`, removed it with `--from`, or the placement was deleted. Universal clients and disabled clients are never missing a skill. | Place it in one client with `agentx skill place <name> --to <client>`, or in every client it is missing from with [`agentx skill place <name>`](#put-back-placements). |
| `source removed` | The source the skill came from is no longer added on this machine. The skill keeps working. | Add the source again. See [Bring back a removed source](#bring-back-a-removed-source). |
| `upstream removed` | The last [update check](#check-for-updates) found the skill gone from its source. The skill stays as it is, and agentx does not update it. | Nothing. The next check that finds it in the source clears the state. |
| `not published` | One of your own skills that is not on your account remote. | Publish it with `agentx skill publish <name>`. If another machine removed it, you can remove it here too with `agentx skill remove <name>`. |
| `update available` | The last update check found a newer version in the source. Your library is unchanged. | Read it with `agentx skill diff <name> --update`, then apply it with [`agentx skill update <name>`](#update-a-skill). |
| `merge pending` | Your edits conflict with an update. Your library directory is unchanged. | Resolve the merge and update again, or give it up. See [When your edits conflict](#when-your-edits-conflict). |

A skill can be in more than one state at once, so the row names each of them: `modified, source removed` is a skill you edited whose source you then removed. `displaced` and `missing` are information only, so they do not make a command fail.

Add `--remote` to also list the skills on your account remote that this machine has not installed. See [Install your skills on another machine](#install-your-skills-on-another-machine).

### A skill whose library directory is gone

If a managed skill's directory is deleted from the library outside agentx, the skill has no row. `skill list` names it in a warning instead, with two ways out:

```text
warning: pdf is managed in the account repo but the library holds no skill directory for it; run 'agentx skill add https://github.com/anthropics/skills --name pdf' to install it again, or 'agentx skill remove pdf' to stop managing it
```

- Install it again with `agentx skill add`. This works while the source still holds the version you installed. If the skill changed in the source since you last fetched it, `skill add` refuses and tells you to run `agentx skill remove` first.
- Stop managing it with `agentx skill remove <name>`. This always works. It removes the skill's record and the placements agentx made, and clears the warning. `--from <client>` stops with exit code 6 for such a skill.

If the directory is still there but has lost its `SKILL.md`, the warning names it. Move it aside before you install the skill again, since `skill add` does not write over it.

### Bring back a removed source

A managed skill whose source you removed shows `source removed` until you add that source again:

```sh
agentx source add https://github.com/me/skills
```

This clears the state. Your skill and its placements stay as they are. See [Remove a source](/cli/source#remove-a-source).

## See what you changed

See the edits you made to a managed skill. agentx compares it with its base version: the version you installed or updated to, or last [published to its source](#publish-edits-to-a-shared-source).

```sh
agentx skill diff pdf
```

```text
pdf differs from its base version at 3f2a9c1 in 2 files
diff --git a/SKILL.md b/SKILL.md
index 5d1e2c4..8f0a3b1 100644
--- a/SKILL.md
+++ b/SKILL.md
@@ -3,2 +3,3 @@ name: pdf
 # PDF
 Use this skill to read and fill in PDF forms.
+Always keep the original file.
diff --git a/notes.md b/notes.md
new file mode 100644
index 0000000..2f1c9e0
--- /dev/null
+++ b/notes.md
@@ -0,0 +1 @@
+My own notes.
```

There is one diff per file, and paths are relative to the skill's directory. A moved file shows as one deleted and one added. A skill with no edits prints `pdf matches its base version at 3f2a9c1`.

The diff changes nothing. [Files that do not count](#files-that-do-not-count) never show.

A repository nested in the skill, or anything else git cannot record, such as a named pipe, is left out with a warning naming it. Such a skill never matches its base version:

- `skill list` shows it as `modified`;
- the first line of the diff counts the paths git cannot record, as in `pdf differs from its base version at 3f2a9c1 only in 1 path git cannot record`;
- `skill update` refuses to apply an update to it until you move the path out of the skill.

A skill agentx did not install has no base version to compare with, so `skill diff` stops with exit code 6. For one of your own skills, `skill diff` shows its unpublished edits, against what you last published: see [See what changed](/cli/fork#see-what-changed).

### Files that do not count

agentx skips the files git ignores. They do not make a skill `modified`, they do not show in `skill diff`, and `skill update` keeps them. This covers:

- files the skill's own `.gitignore` names, such as a `node_modules` directory;
- files your global git ignore file names, `~/.config/git/ignore` or the file your `core.excludesFile` setting points to;
- files your operating system or editor leaves behind, such as `.DS_Store`, `Thumbs.db`, `*.swp` and `*~` backups, while the [`ignore_system_files`](/cli/config) setting is on, which it is by default.

A file that was part of the version you installed always counts, even when an ignore rule names it. The skill's own `.gitattributes` applies too: a file that differs only in line endings the skill asks git to normalise is not a change.

### Get the original back

agentx does not undo edits for you. To discard your edits, remove the skill and add it again:

```sh
agentx skill remove pdf
agentx skill add anthropics/skills --name pdf
```

Removing deletes the skill and all your edits, so run `agentx skill diff pdf` first and save what you want to keep. Adding it again installs the version from the source's last fetch, which may be newer than yours. Pass `--copy` or `--to` again if you used them: removing the skill forgets them.

## Check for updates

Look for newer versions of the skills you installed, including the ones you forked:

```sh
agentx skill check-updates
```

```text
✓ checked 3 skills from 2 sources: 1 update available
  pdf  update available  3f2a9c1 -> 8b1e0f4  2 files
    modified  SKILL.md
    added     forms.md
Apply an update with agentx skill update <name>, or read it first with agentx skill diff <name> --update.
```

agentx fetches the source of each managed skill and the upstream of each skill you forked. It uses your git setup, so your credentials work. It then lists each skill that has a newer version, with the files that version changes. For a forked skill, see [Take a new upstream version](/cli/fork#take-a-new-upstream-version).

Nothing is applied. Your library, your clients and your edits stay exactly as they were. agentx records the newer upstream version it found so that you can read it, apply it with [`agentx skill update`](#update-a-skill), and so that `agentx skill list` shows `update available` for the skill:

```text
1 skill
  pdf  managed  current, update available  https://github.com/anthropics/skills/skills/pdf  4 placements
```

Each check lists every update available, including the ones an earlier check found.

With an account remote set, the check also fetches it and lists each of your own skills placed on this machine that another machine published changes to. Take those changes in with `agentx skill update <name>`:

```text
  notes  published from another machine  4c2d1e9 -> 7a0b3f2  1 file
    modified  notes.md
```

What another machine published is not recorded, so `agentx skill list` does not show it and `agentx skill diff --update` cannot read it: run the check again to see it, or `agentx skill update <name>` to take it in. If the account remote cannot be reached, the check warns, still checks your other sources, and exits with code 3.

The desktop app runs this check once when it starts. See [Update checks](/cli/serve#update-checks).

### Read an update

Show what an update changes, file by file:

```sh
agentx skill diff pdf --update
```

```text
the update of pdf at 8b1e0f4 differs from its base version at 3f2a9c1 in 2 files
diff --git a/SKILL.md b/SKILL.md
...
```

The diff compares the version you installed with the version the last check found. It leaves out your own edits, which `agentx skill diff pdf` shows, and it needs no network. If no check has found an update for the skill, the command stops with exit code 6 and tells you to run `agentx skill check-updates`.

### A skill its source no longer holds

If a skill's directory is deleted from its source, or loses its `SKILL.md`, the check says so:

```text
✓ checked 3 skills from 2 sources: no update available, 1 upstream removed
  docx  upstream removed  https://github.com/me/skills/docx at 8b1e0f4
```

The skill stays in your library as it is, shows `upstream removed` in `agentx skill list`, and agentx does not update it. If the source brings it back, the next check clears the state.

### When a source cannot be reached

A source that cannot be fetched is one warning that names it, the reason and the skills it left unchecked:

```text
warning: https://github.com/me/skills: git fetch: fatal: could not read from remote repository; not checked: docx
```

The check goes on with every other source and records what it finds, then exits with the code for that failure, `3` for a source it cannot reach. Updates found earlier for the skills of that source are kept.

### Sources you removed

The check skips the skills of a source you removed with `agentx source remove`: it does not fetch the source and keeps what an earlier check found for them. Add the source again to check them.

## Update a skill

Apply the update a check found:

```sh
agentx skill update pdf
```

```text
✓ updated pdf from 3f2a9c1 to 8b1e0f4, 1 copy placement refreshed
```

agentx replaces the skill's library directory with the newer version and records it as the version you have. Every client that links to the library sees the new version at once. `agentx skill list` shows the skill as `current` again, and its `update available` is gone.

For a skill of a source, the update applies the version the last check found, the one `agentx skill diff pdf --update` shows, and needs no network. agentx updates a skill only when you run this command. If you edited the skill, agentx keeps your edits. See [A skill you edited](#a-skill-you-edited).

Files your ignore rules name stay: a `.DS_Store`, an editor's backup file or an ignored `build` folder (see [Files that do not count](#files-that-do-not-count)). If the newer version ships a file at the same path, its file replaces yours.

Update every skill that has an update:

```sh
agentx skill update --all
```

```text
✓ updated 2 skills, 1 edited skill merged cleanly, 1 copy placement refreshed
  pdf   3f2a9c1 -> 8b1e0f4  1 copy placement refreshed
  xlsx  5d6e7f8 -> 9a0b1c2  edits merged cleanly
```

If no check has found an update for the skill, the command says it is up to date as of the last check and changes nothing. Run `agentx skill check-updates` to look again.

A copy placement is handled on its own:

- A copy that holds the version you are replacing gets the new version, and keeps the files your ignore rules name in it.
- A copy you edited in place is kept exactly as it is and skipped, with the warning for a [copy that differs from the library](#a-copy-that-differs-from-the-library).
- A copy agentx cannot read is kept as it is and skipped, with a warning that says why.

If a newer version gives the skill another name, the skill keeps the name you installed it under, and the update says so.

If the skill changes while the update runs, for example because your editor saves a file, agentx stops with exit code 6. Run the command again. An interrupted update finishes on the next agentx command.

If a file of the skill changes while the update writes it, agentx stops with exit code 6 and says that recovery is required. To finish the update, restore the file the error names. To keep your change, move the journal file in `~/.agentx/mutations` aside.

### Update to what another machine published

Your own skills travel between your machines through the [account remote](/cli/source#add-your-account-remote): the ones you created with `agentx skill new`, forked with `agentx skill fork`, or installed from the account remote. Update them to the latest version you published from another machine the way you take an update:

```sh
agentx skill check-updates
agentx skill update --all
```

```text
✓ updated notes to the latest published version: "Tighten the summary steps"
no skill was updated from upstream
```

- `agentx skill check-updates` lists what the account remote holds that this machine lacks as `published from another machine`. Checking first is optional: `agentx skill update <name>` fetches the account remote itself.
- `agentx skill update <name>` updates one skill to the latest published version and shows the message it was published with. `agentx skill update --all` does so for every one of your own skills on this machine.
- If both machines changed the skill, agentx merges the two and prints `✓ merged the latest published version of notes with your local edits`. The skill then shows as `modified` until you publish it.
- A skill you forked from a source is first updated to the latest published version, then to its new upstream version, as two commits.
- Edits you have not published are recorded on the skill first, and what the account remote holds is merged with them. They stay unpublished until you [publish](#publish-a-skill) them. Publish with `-m` to publish them under your own message.
- Update before you publish: [`agentx skill publish`](#publish-a-skill) never merges, and stops with exit code 6 when another machine published changes and this machine has changes of its own.
- When both machines changed the same lines, the merge waits for you: see [Resolve a conflict](/cli/fork#resolve-a-conflict). Resolve it, then run `agentx skill update <name>` again.
- A skill with no upstream (one you created with `agentx skill new`, or forked from an unmanaged or a plugin's skill) that has nothing new on the account remote is `up to date with the account remote`. One you never published, or one another machine removed, has no branch there, and the update tells you to run `agentx skill publish <name>`.
- If Git cannot reach the account remote, the update of a skill with no upstream stops with exit code 3. A skill you forked from a source gets a warning and still takes its new upstream version.

### A skill you edited

A skill you changed since you installed it keeps your changes: agentx merges them into the newer version, the way git merges two branches, with the version you installed as their common base. When your changes and the update change different lines, the merge is clean and the update applies at once:

```text
✓ updated docx from 3f2a9c1 to 8b1e0f4 and merged its edits cleanly
```

The skill is then at the new version with your changes on top of it, so `agentx skill list` still shows it as `modified`, and `agentx skill diff docx` shows your changes against the new version. Files your ignore rules name are not part of your edits and are kept as for any update. A file you added inside a folder the update renamed stays where you put it. A copy that still held the version you installed, or your edited version, gets the merged one.

Git merges line by line, and changes to lines next to each other conflict, so a short file conflicts more often than you might expect. Read the update with `agentx skill diff docx --update` before you apply it.

### When your edits conflict

When your changes and the update change the same lines, agentx leaves your library as it is. Your agents keep using the skill as you left it. The merge waits in a separate Git folder, `~/.agentx/merges/<name>`.

`skill update` stops with exit code 4 and lists the files that conflict, each with what `git status` says of it:

```text
docx conflicts with its update from 3f2a9c1 to 8b1e0f4 in 2 files
SKILL.md: both modified
logo.png: both modified
error: docx conflicts with its update in 2 files, so the merge is pending and the library directory was left as it is
hint: resolve it with git in /home/me/.agentx/merges/docx/docx ('git add' each file you resolved, or 'git checkout --ours|--theirs <file>' then 'git add'; 'git commit' is optional), then run 'agentx skill update docx' again to apply it, or 'agentx skill update docx --abort' to give it up
```

As in `git status`, "us" is your library directory and "them" the update: a file you deleted and the update changed reads `deleted by us`, and one the update added where you had added a file too reads `both added`. Files your ignore rules name are not part of your edits, so they never conflict and stay as they are.

The folder holds a normal Git merge. Work in the folder the hint names. Conflict markers are longer than any line of the skill that looks like one, such as a `=======` rule. The merge stays until you finish it or give it up, and `agentx skill list` shows the skill as `merge pending`. Meanwhile:

- `skill fork`, and `skill remove` without `--from` or with `--from universal`, stop with exit code 4 and change nothing.
- Everything else works as usual: placing the skill, `skill place --force` included, removing it from one client, `skill diff`, and update checks, which may find a newer version still.

With `--all`, a skill whose edits conflict is left with its merge pending and the other skills are still updated. The run then exits with code 4, or 6 if other skills were not updated for other reasons.

### Finish the merge

Resolve the merge with Git in the folder the hint names:

```sh
cd ~/.agentx/merges/docx/docx
git checkout --theirs logo.png   # take the update's version of a file whole, or --ours for yours
git add logo.png
```

Edit a file that conflicts to keep what you want from both sides, then `git add` it. `git status`, `git diff` and `git commit` work there as in any merge; committing is optional. Then run the update again:

```sh
agentx skill update docx
```

```text
✓ updated docx from 3f2a9c1 to 8b1e0f4 with the merge you resolved
```

agentx applies the merge as it applies a clean one: your library directory takes the merged files, copies are refreshed, and the worktree is removed, so leave it with `cd` if your shell is still in it.

- Only what you `git add`ed is applied, as `git commit` would record it. A change you made after `git add`, or a new file you never added, is removed with the worktree.
- It applies the version the merge started with, even if a check has found a newer one since. That newer one stays as the skill's next update.
- `agentx skill update --all` applies it too, with the other updates.
- Until every file is resolved, the update lists the files that are left and stops with exit code 4 again, changing nothing.

If you changed the skill's library directory while the merge was pending, the update stops with exit code 6. Give the merge up and update again.

### Give the merge up

```sh
agentx skill update docx --abort
```

```text
✓ gave up the merge of docx; the library directory is as it was
```

This removes the worktree and whatever you resolved in it. Your library directory, its placements and the update agentx found are left exactly as they were, so `agentx skill update docx` merges again from scratch.

### When a skill is not updated

| Case | Exit code | What to do |
|---|---|---|
| A [merge pending](#when-your-edits-conflict) with files still to resolve | 4 | Finish the merge. The update lists the files that are left. |
| You removed the skill's source | 5 | Run the `agentx source add` command in the hint. With `--all`, the skill is skipped with a warning that names the same command. The update found earlier is kept. |
| The skill shows `upstream removed` | 6 | Nothing. The skill stays as it is. |
| A skill agentx did not install | 6 | Nothing. It has no update to apply. |
| One of your own skills with no upstream, such as a skill you created, and no account remote set | 6 | Add an account remote. The update then brings the skill to what your other machines published. See [Update to what another machine published](#update-to-what-another-machine-published). |
| The library directory is gone | 6 | Install it again with `agentx skill add <source> --name <name>`, or stop managing it with `agentx skill remove <name>`. See [A skill whose library directory is gone](#a-skill-whose-library-directory-is-gone). |
| agentx cannot read the skill's record in the account repo | 6 | Run `agentx doctor` and check the account repo it names. |
| The library directory is a symlink to a directory of yours | 6 | Replace the link with the directory it points to, then update again. |
| The skill holds something git cannot record, such as a nested repository | 6 | Move it out of the skill, then update again. |

With `--all`, agentx updates every skill it can and names each one it could not. It then exits with the code those skills share, or 6 if they differ. A skill whose source you removed is skipped and does not change the exit code.

## Publish a skill

Publish one of your own skills, one you created with `agentx skill new` or forked with `agentx skill fork`, to your [account remote](/cli/source#add-your-account-remote) so your other machines can install it and get what you change:

```sh
agentx skill publish release-notes -m "Cover reverted pull requests"
```

```text
✓ published release-notes as 4c2e9a1
```

- Your edits stay on this machine until you publish them. Publishing records them as one commit on the skill's history, then pushes it. There is no separate commit step.
- Give the commit a message with `-m`. Its first line is the subject. Without `-m`, agentx writes one that names the skill, the files you changed and this machine, such as `release-notes: edit SKILL.md (laptop)`.
- With `-m`, agentx publishes all your unpublished changes as one commit under your message. A rename or an upstream update keeps its own commit.
- Publish a skill the first time by name. Its push creates the skill's branch on the account remote.
- Run `agentx skill publish` with no name to publish every skill of your own that the account remote already holds. `-m` then gives the message of each commit it records. A bare publish never creates a branch: it skips each skill shown as `not published`, one you never published or one another machine removed, and names the command that publishes it:

  ```text
  warning: release-notes is not published: run 'agentx skill publish release-notes' to publish it
  ```

  A bare publish never covers a skill you installed from a shared source either: name it to [publish it to its source](#publish-edits-to-a-shared-source).
- [Files that stay local](/cli/fork#files-that-stay-local), such as a `.DS_Store`, are never published.
- Each skill goes to its own branch, `skills/<name>`. Publishing one skill leaves your other skills where they are.
- If another machine published changes first, publishing stops with exit code 6 and changes nothing. Run [`agentx skill update <name>`](#update-to-what-another-machine-published), then publish again. agentx never forces a push.
- When the remote's host declines the push, for example a hook or a protected branch, publishing stops with exit code 6 and names the host's reason, with up to three lines the host wrote:

  ```text
  error: the account remote declined skills/release-notes: pre-receive hook declined: no pushes on Fridays
  hint: agentx never forces a push; once the account remote takes it, run 'agentx skill publish release-notes' again
  ```

  There is nothing to update: fix what the host says, then publish again.
- When the remote does not let this machine push, publishing stops with exit code 3. The hint says what to fix:
  - Credentials that only allow reading, or none: check the git credential helper or SSH key you use for the remote.
  - A host SSH does not trust yet: connect to it once with `ssh` to add its key to `known_hosts`.
  - An organisation that requires single sign-on or an IP allow list: authorise your token or key for the organisation, or allow this machine's IP address.
- Publishing needs an [account remote](/cli/source#add-your-account-remote). Without one, it stops with exit code 6 and names `agentx source add <url> --account`.
- A skill agentx does not manage has no source to publish to: fork it with `agentx skill fork <name>` to make it one of your own.
- To delete a skill's branch from the remote, remove the skill with [`agentx skill remove <name> --remote`](/cli/fork#remove-a-skill-of-your-own).

### Publish edits to a shared source

Push the edits of a skill you installed from a shared source back to that source, for example a fix to a skill of your team's repository:

```sh
agentx skill publish pdf -m "Keep the original file"
```

```text
✓ published pdf to main of https://github.com/acme/skills as 9b1d7e3
```

- Name the skill. A bare `agentx skill publish` never pushes to a shared source.
- No account remote is needed. Publishing to a shared source does not read or fetch yours.
- agentx writes one commit on the branch the skill is installed from: the source's default branch, or the branch you pinned it to. The commit changes the skill's folder alone, and everything else on the branch stays as it is.
- The commit carries your own Git identity. Set it first with `git config --global user.name "Your Name"` and `git config --global user.email you@example.com`: without it, publishing stops with exit code 6. The commit carries no agentx data.
- Give the commit a message with `-m`. Without `-m`, the message is `Update <folder>`, such as `Update skills/pdf`, or `Update <directory name>` for a skill at the root of its repository.
- Afterwards the skill stays managed and shows as `current`: the version you published is the one it compares with.
- A skill with no edits has nothing to publish. agentx says so without fetching anything.
- When the source changed the skill since you installed it, publishing stops with exit code 6 and pushes nothing. Your edits stay where they are. Take the change in with [`agentx skill update <name>`](#update-a-skill), then publish again:

  ```text
  error: https://github.com/acme/skills changed pdf since it was installed, so it was not published
  hint: run 'agentx skill update pdf' to take the change in, then publish again
  ```

- While a merge with an update is pending, publishing stops with exit code 4: [finish the merge](#finish-the-merge) or give it up first.
- When you removed the skill's source from this machine, publishing stops with exit code 5: add it again with `agentx source add <url>`.
- When the source's host declines the push, for example a hook or a protected branch, publishing stops with exit code 6 and names the host's reason. Fix what the host says, then publish again.
- When the source does not let this machine push, publishing stops with exit code 3. Check the git credential helper or SSH key you use for it, as for [your account remote](#publish-a-skill).
- A skill installed from a tag or a commit has no branch to publish to: publishing stops with exit code 6. Add the source at a branch with `agentx source add <url>#<branch>`, update the skill, then publish again.
- A symlink you add to the skill is never pushed: publishing stops with exit code 6. Replace it with the file it leads to, or remove it.
- When the skill holds a file agentx would not install, or something Git cannot record, publishing stops with exit code 6. Move it out of the skill, then publish again.
- When the source no longer holds the skill, publishing stops with exit code 6. Run `agentx skill check-updates` once the source holds it again, or remove the skill.
- If publishing stops with exit code 3 or 6 for another reason, or succeeds with a warning, follow the hint, then publish again if it says so.

### Two skills with one name

Every skill of your own has a permanent id. A skill you create on two machines under the same name is two skills, with two ids. agentx keeps them apart: once one is published, publishing or updating the other stops with exit code 6:

```text
error: the account remote's skills/release-notes is a different skill than release-notes on this machine, so release-notes cannot be published
hint: rename yours with 'agentx skill rename release-notes <new>', then publish that one
```

[Rename](/cli/fork#rename-a-skill-of-your-own) yours, then publish it under its new name. Publishing the renamed skill keeps the other skill's branch, since it has another id. A remote branch whose history records no id stops the same way, since nothing tells that it holds the same skill.

## Remove a skill

From one client:

```sh
agentx skill remove pdf --from cursor
```

```text
✓ removed pdf from cursor: 1 placement
  cursor  symlink  /home/me/.cursor/skills/pdf
```

From the machine altogether:

```sh
agentx skill remove pdf
```

```text
✓ removed pdf from the library: 4 placements
  claude-code  symlink  /home/me/.claude/skills/pdf
  cursor       copy     /home/me/.cursor/skills/pdf
  codex        library  /home/me/.agents/skills/pdf
  gemini-cli   library  /home/me/.agents/skills/pdf
  deleted /home/me/.agents/skills/pdf and refs/heads/managed/pdf
```

Without `--from`, agentx takes away every placement, the library directory, the record of where the skill came from and what the settings remembered about it. With `--from <client>`, only those clients' placements go; the library keeps the skill.

While a skill has a [merge pending](#when-your-edits-conflict), removing it from the machine stops with exit code 4 and removes nothing. Removing it from one client works as usual.

If the skill's library directory is gone, `agentx skill remove <name>` still works. It removes the record and the placements agentx made. `--from <client>` stops with exit code 6. See [A skill whose library directory is gone](#a-skill-whose-library-directory-is-gone).

From every client, by name:

```sh
agentx skill remove pdf --from universal
```

`--from universal` does the same as leaving `--from` out. Use it on its own: next to a client that is not universal, it stops with exit code 1.

### What agentx deletes

agentx deletes a placement only when it made it:

- a symlink pointing at the library directory, and
- a copy agentx placed and recorded.

Everything else is left exactly where it is and named in the output:

- a directory you made by hand,
- a link of yours pointing somewhere else, even when following it ends up in the library,
- a directory holding the same version that agentx never recorded as a copy,
- a file.

agentx deletes only a link that points straight at the library entry. A link of yours stays, even if it leads to the library through another link:

```text
warning: /home/me/.claude/skills/pdf points at /home/me/mylinks/pdf, not at /home/me/.agents/skills/pdf and was left as it is; it no longer leads to pdf
warning: /home/me/.cursor/skills/pdf is a directory agentx did not place there and was left as it is; cursor still sees it
✓ removed pdf from the library: 2 placements, 2 placements left in place
  ...
```

Here `~/mylinks/pdf` points at the library entry. The removal deletes that entry, so your link stays but leads nowhere. A link of yours that leads somewhere else keeps working, and the warning names the client that still sees the skill.

agentx removes a copy it placed even if you changed it, and warns you:

```text
warning: cursor's copy of pdf was different from the library; removing it deleted those changes (/home/me/.cursor/skills/pdf)
```

Take a copy of anything you want to keep before removing it.

### Clients that read the library

A [universal client](#clients-that-see-every-skill) reads the library directly, so it has no placement of its own to remove. A skill leaves every universal client at once or none of them:

```sh
agentx skill remove pdf --from codex
```

```text
error: codex reads the library directly, so pdf cannot be removed from it alone
hint: take pdf off the machine with 'agentx skill remove pdf --from universal', which removes it from claude-code, codex, cursor, gemini-cli
```

agentx changes nothing. To take the skill off the machine, run the command in the hint. It lists every client that loses the skill.

### After a removal

After a removal, agentx checks each client again. If a client still sees the skill, for example through a directory agentx did not place, agentx warns and names the path:

```text
warning: codex still sees pdf at /home/me/.codex/skills/pdf, which agentx did not place there
```

### Your own skills

Removing one of your own skills from the machine also deletes its local history. Add `--remote` to delete it from your account remote too. See [Remove a skill of your own](/cli/fork#remove-a-skill-of-your-own).

`--remote` applies only to your own skills, the ones on your account remote. For a skill of another source, or one with no source, agentx refuses it with exit code 6 and changes nothing. Remove the skill from this machine with `agentx skill remove <name>`.

## Exit codes

For what each code means, and for codes 2 and 9, see [Exit codes](/cli/output#exit-codes). These causes are special to `agentx skill`:

| Code | Typical causes |
|---|---|
| 1 | Flags that contradict each other, such as `--all` with `--name`, `--except` without `--all`, `--remote` with `--from <client>`, or `--from universal` with a client that is not universal. A ref other than the source's pin. `skill add` given the name of a library skill, or, with no source, given `--fetch` or neither `--name` nor `--all`. |
| 3 | A source or the account remote cannot be fetched, or does not let this machine push. |
| 4 | A merge is pending: `skill update` left one, or one blocks the command. See [When your edits conflict](#when-your-edits-conflict). |
| 5 | A source, skill, path or configuration you named does not exist, or you removed the skill's source. For a removed source, the hint names the `agentx source add` command that brings it back. |
| 6 | The library already holds another skill of that name; a directory differs and `--force` is not given; another machine published first; the host declined the push; `--remote` for a skill that is not your own; `--from` names a universal client; a managed skill whose record agentx cannot read (run `agentx doctor`). An interrupted change must be resolved first: the message names the file to restore. To keep the file as it is, move the journal in `~/.agentx/mutations` aside. For one of your own skills, see [Your own skills](/cli/fork#exit-codes). |
| 7 | Another agentx command is running. Retry when it finishes. |
| 8 | agentx cannot read or write the account repo. Run `agentx doctor`. |
| 10 | agentx could not read its settings file, or hit an error it has no better answer for. Run `agentx doctor`. |
