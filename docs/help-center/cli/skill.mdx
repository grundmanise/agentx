---
title: "agentx skill"
description: "Install skills from a source into your library, place them in your agent clients, see and revert what you changed, repair their placements, remove them again, and see what you have."
---

Your library is one directory, `~/.agents/skills`, that holds every skill agentx manages for you. Installing a skill puts it there once and links it into each agent client, so every client sees the same files and an update reaches all of them at once.

## Install a skill

```sh
agentx skill add anthropics/skills --skill pdf
```

```text
✓ added https://github.com/anthropics/skills at 8c41d07: 17 skills
✓ installed pdf from https://github.com/anthropics/skills under skills/pdf at 3f2a9c1, source fetched 2026-09-22T10:00:00Z: 4 placements
  claude-code  symlink  ~/.claude/skills/pdf -> ~/.agents/skills/pdf
  codex        library  ~/.agents/skills/pdf
  cursor       symlink  ~/.cursor/skills/pdf -> ~/.agents/skills/pdf
  gemini-cli   library  ~/.agents/skills/pdf
  always available to universal clients: codex, gemini-cli
```

Each row is one client's placement: the link or copy in its own skills directory, or the library entry itself for a client that reads the library. Cursor also reads Claude Code's skills directory, so it sees the skill there too; that path is Claude Code's row. `--json` lists every path each client sees the skill through.

If the source is not on this machine yet, `skill add` adds it first, as [`agentx source add`](/cli/source) would, and the source stays added even if the install then fails. Name the source by its URL for this: a source id only works for a source you already added. If you removed the source and a skill installed from it is still in your library, installing by its id tells you the command that adds it again:

```text
error: no source with id 1c9d0b7e4a2f6d38: https://github.com/anthropics/skills was removed, and the skills installed from it still name it
hint: run 'agentx source add https://github.com/anthropics/skills' to add it again
```

A source you already added is not fetched again. The install reads what that source last fetched, so it never surprises you with a version you have not seen, and the result says when that fetch was. Add `--fetch` to fetch the source again first, or run `agentx source fetch`:

```sh
agentx skill add anthropics/skills --skill pdf --fetch
```

To install from another branch or tag than the one the source is pinned to, change the pin with `agentx source add <url>#<ref>` first.

Name the skill with `--skill` when the source holds more than one. `--skill` and `--except` match the `name` in the skill's `SKILL.md` frontmatter in any case, or its directory name when the frontmatter has no name, as the vercel skills CLI does. If a path already narrows it to a single skill, leave `--skill` out:

```sh
agentx skill add anthropics/skills/skills/pdf
```

### Install several at once

Give `--skill` once for each skill you want:

```sh
agentx skill add anthropics/skills --skill pdf --skill xlsx --skill docx
```

Or take the whole source and leave out what you do not want:

```sh
agentx skill add anthropics/skills --all --except artifacts-builder
```

`--all` and `--skill` do not mix, and `--except` needs `--all`. Skills install in the order the source lists them, whatever order you name them in. `--all` works with a source you have not added yet too: it is added once, and then every skill of it installs.

One command installs them all: the files come down in one fetch, the versions are recorded in one write to the account repo, and the whole run is one change agentx can finish after an interruption. Thirty skills cost the same git work as one; the time they take is the time their files take.

If one skill cannot be installed, the rest still land. agentx names the one it skipped and why, and exits non-zero:

```text
warning: xlsx: the library already holds xlsx at ~/.agents/skills
✓ installed pdf from https://github.com/anthropics/skills under skills/pdf at 3f2a9c1, source fetched 2026-09-22T10:00:00Z: 4 placements
  ...
error: 1 of 3 skills could not be installed: xlsx: the library already holds xlsx at ~/.agents/skills
```

agentx also refuses a skill whose directory in the source carries a control character, or opens or closes with a space:

```text
error: pdf comes from " skills/pdf", which is not a directory the account repo can record
hint: the import commit that records where a skill came from carries the directory on one line of a trailer, so it can hold no control character and no surrounding space; rename the directory upstream, or install another skill
```

agentx records where a skill came from on one line of its commit. A directory name that does not fit on one line would be read back as a different directory, or as none at all, leaving a skill you could never update or revert. Ask the source to rename the directory, or install a different skill.

### Clients that see every skill

Some clients, such as Codex and Gemini CLI, read the library directly. They are universal clients: they get no link of their own, because the library entry is what they see. So is any client whose skills directory you made a symlink to the library, or the library a symlink to it: both are one directory. A client that reads such a directory is universal too: Cursor reads Claude Code's skills directory, so once `~/.claude/skills` is a symlink to the library, Cursor reads the library as well. Every other client gets a symlink in its own skills directory, pointing at the library.

A universal client sees every skill in your library, even when you disabled it with `agentx config disable` or left it out of `--to`. Each install ends with a line naming every universal client installed on this machine, since the skill is always available to them whatever you chose:

```text
  always available to universal clients: codex, gemini-cli
```

The line is left out when no universal client is installed. To take a skill away from the universal clients, remove it from the library, see [Clients that read the library](#clients-that-read-the-library).

### Choose where it goes

By default a skill is placed in every enabled configuration. Name the ones you want instead:

```sh
agentx skill add anthropics/skills --skill pdf --to claude-code --to cursor
```

`--to` replaces the default targets for that install, including configurations you have disabled with `agentx config disable`. It decides which clients get a placement; the universal clients see the skill whatever it names.

### Copy instead of link

```sh
agentx skill add anthropics/skills --skill pdf --copy
```

Use `--copy` for a client that cannot follow a symlink. agentx remembers which configurations hold a copy and keeps them that way: installing the skill again, `agentx skill place` and `agentx config enable --place-all` give those configurations a copy even without `--copy`.

### What happens to what is already there

- A library directory holding exactly this version is adopted: agentx records where it came from and changes nothing on disk.
- A library directory holding anything else stops that skill with exit code 6. Remove it, or keep it and install under another name later. In a run of several skills only that skill is stopped.
- A placement that already points at the library is left alone.
- A placement that is a real directory holding exactly this version is replaced by a link and reported as adopted. A copy agentx placed there itself stays a copy and is not reported as adopted.
- A copy agentx placed that is different from the library is kept exactly as it is and skipped, with a warning. See [A copy that differs from the library](#a-copy-that-differs-from-the-library).
- A placement that is a link somewhere else is left alone, even if what it points at holds the same files: where your skill lives is your choice.
- Anything else in the way is left untouched, with a warning naming the path.
- A client skills directory agentx cannot write – one owned by somebody else, one on a read-only mount, or one macOS has not granted access to – is skipped with a warning. The rest of the install still happens, and the summary counts the placements it skipped.

Your files are never overwritten by an install.

If two commands try to install the same name at once, one of them wins and the other is refused. The one that loses leaves nothing behind: no half-written directory, and nothing for the next command to clean up.

### A copy that differs from the library

A copy agentx placed stops matching the library when you edit the copy or when the skill in the library changes. `agentx skill place` and `agentx config enable --place-all` keep that copy exactly as it is and skip it, with a warning:

```text
warning: cursor's copy of pdf is different from the library, so it was left unchanged (~/.cursor/skills/pdf)
  to replace it with the library version: agentx skill remove pdf --from cursor && agentx skill place pdf --to cursor --copy
```

Installing the skill again keeps and skips a copy you edited the same way, with the same warning. When the skill in the library changed, the install stops with exit code 6 before it reaches the copy, as described in [What happens to what is already there](#what-happens-to-what-is-already-there).

The summary counts the copy as a skipped placement. agentx does not record what a copy held when it placed it, so the warning does not say which side changed.

To replace the copy with the library version, run the commands on the second line of the warning. Removing the copy deletes what it holds, so save anything you want to keep first. `--copy` makes the new placement a copy again, as agentx had recorded for that client. For a skill whose name starts with `-`, the commands put the name last, after `--`, for example `agentx skill remove --from cursor -- -pdf`.

With `--json`, the warning is one `log` event whose `message` holds both lines, joined by `; `.

### What is left out of the import

A skill directory holds regular files and directories. Anything else – a symlink or a git submodule inside the skill – is left out, with a warning naming it. The library directory then differs from the upstream one, and what agentx records as the installed version is what it actually installed.

## Place a skill you already have

Put a skill the library already holds into another client:

```sh
agentx skill place pdf --to cursor
```

```text
✓ placed pdf in 1 configuration
  cursor  symlink  ~/.cursor/skills/pdf -> ~/.agents/skills/pdf
  always available to universal clients: codex, gemini-cli
```

The first line counts the configurations you placed into. Each client you named gets one row, its own placement, as after an install. If agentx left a client's path alone and that client still sees the skill through another client's skills directory, its row shows that path instead, so the output still tells you the client has the skill.

Name each client with `--to`, once for each. Add `--copy` for a client that cannot follow a symlink; agentx remembers the choice, as it does for `agentx skill add --copy`. To turn a recorded copy back into a symlink, take it away with `agentx skill remove pdf --from cursor`, then place the skill again with `agentx skill place pdf --to cursor`.

This is the second half of `agentx skill add` on its own, so everything that command does about what is already at the path applies here too: a link that already points at the library is left alone, a directory holding exactly this version is adopted, and anything else is left where it is with a warning.

An adopted directory becomes one agentx will delete when you remove the skill, so the run names every path it adopted. This holds with `--copy` too, where agentx writes nothing and only records the choice.

A universal client, such as Codex or Gemini CLI, reads the library directly. Placing into one makes no second entry: it already sees the skill, and the last line names every universal client whichever clients you place into.

Use `skill place`, not `skill add`, for a skill that is already in your library. `skill add` installs from a source, so given the name of a library skill it stops with exit code 1 and names the command to run instead:

```text
error: pdf is already in the library; skill add installs a skill from a source
hint: to place it in more clients, run 'agentx skill place pdf --to cursor'
```

The hint keeps the `--to` and `--copy` you gave. Without `--to`, it shows `--to <configuration>`: replace that with the client you want. A source always comes first: a source URL, `owner/repo` or a source id installs from that source, even when a skill in your library has the same name.

## Remove a skill

From one client:

```sh
agentx skill remove pdf --from cursor
```

```text
✓ removed pdf from cursor: 1 placement
  cursor  symlink  ~/.cursor/skills/pdf
```

From the machine altogether:

```sh
agentx skill remove pdf
```

```text
✓ removed pdf from the library: 4 placements
  claude-code  symlink  ~/.claude/skills/pdf
  cursor       copy     ~/.cursor/skills/pdf
  codex        library  ~/.agents/skills/pdf
  gemini-cli   library  ~/.agents/skills/pdf
  deleted ~/.agents/skills/pdf and refs/heads/managed/pdf
```

Without `--from`, agentx takes away every placement, the library directory, the record of where the skill came from and what the settings remembered about it. With `--from <client>`, only those clients' placements go; the library keeps the skill.

From every client, by name:

```sh
agentx skill remove pdf --from universal
```

This is the same removal as leaving `--from` out, with the same output. A universal client reads the library entry itself, so removing a skill from the universal clients means removing it from the library, which takes it from every client. Give `--from universal` on its own. Next to a client that is not universal it stops with exit code 1 and removes nothing; next to a universal client it is refused as that client is, see [Clients that read the library](#clients-that-read-the-library).

### What agentx will and will not delete

agentx deletes a placement only when it made it:

- a symlink pointing at the library directory, and
- a copy agentx placed and recorded.

Everything else is left exactly where it is and named in the output:

- a directory you made by hand,
- a link of yours pointing somewhere else, even when following it ends up in the library,
- a directory holding the same version that agentx never recorded as a copy,
- a file.

agentx decides by the name a link holds, never by where following it leads, so a link of yours is yours whatever it resolves to:

```text
warning: ~/.claude/skills/pdf points at ~/mylinks/pdf, not at ~/.agents/skills/pdf and was left as it is; it no longer leads to pdf
warning: ~/.cursor/skills/pdf is a directory agentx did not place there and was left as it is; cursor still sees it
✓ removed pdf from the library: 2 placements, 2 placements left in place
  ...
```

Here `~/mylinks/pdf` points at the library entry, so once the removal deletes that entry your link stays but no longer leads to the skill, and the warning says so. A link of yours that does not lead through anything the removal deletes keeps working, and the warning says which client still sees the skill.

A copy agentx recorded is removed as you asked, even when it no longer holds the library's version of the skill. agentx warns, naming whose copy it was and its path, rather than letting the content go quietly:

```text
warning: cursor's copy of pdf was different from the library; removing it deleted those changes (~/.cursor/skills/pdf)
```

Take a copy of anything you want to keep before removing it.

### Clients that read the library

Universal clients, such as Codex and Gemini CLI, read `~/.agents/skills` directly, so there is no placement of their own to remove. A skill leaves every universal client at once or none of them:

```sh
agentx skill remove pdf --from codex
```

```text
error: codex reads the library directly, so pdf cannot be removed from it alone
hint: take pdf off the machine with 'agentx skill remove pdf --from universal', which removes it from claude-code, codex, cursor, gemini-cli
```

agentx refuses before it changes anything, also when `--from` names other clients as well, `universal` included, and also when the universal client is disabled. The hint lists every client that sees the skill through the library or through a link or copy agentx would delete, including one that reads another client's skills directory, as Cursor reads Claude Code's. It also lists a client whose link of yours ends up in the library: the removal leaves your link, but the link no longer leads anywhere. A directory of your own is not counted: the removal leaves it. Run the command in the hint to remove the skill everywhere, or keep the skill.

A client that is universal because it reads a skills directory linked to the library is refused the same way, even when a link in its own skills directory is still there. With `~/.claude/skills` a symlink to the library, Cursor reads the library through it, so `agentx skill remove pdf --from cursor` stops with exit code 6, `cursor reads the library directly, so pdf cannot be removed from it alone`, and leaves `~/.cursor/skills/pdf` where it is. Delete that link yourself if you no longer want it, or take the skill off the machine with `--from universal`.

### After a removal

A client may still see a skill through another client's directory: Cursor reads Claude Code's skills directory, for instance. agentx rescans and reports what the client sees now, so the output tells you whether the skill is really gone from it.

Removing a skill from the machine warns for every client that still sees it afterwards, naming the path:

```text
warning: codex still sees pdf at ~/.codex/skills/pdf, which agentx did not place there
```

Universal clients, such as Codex and Gemini CLI, read the library, so removing the library entry is all agentx can do for them. A directory of their own under the same name stays, and the warning says where it is.

### A skill whose library directory is gone

If a managed skill's directory was deleted from the library outside agentx, `agentx skill list` warns about it until you install it again or remove it. Removing it always works, whatever the source holds now:

```sh
agentx skill remove pdf
```

```text
✓ removed pdf, which the library no longer held: 2 placements
  claude-code  symlink  ~/.claude/skills/pdf
  cursor       copy     ~/.cursor/skills/pdf
  deleted refs/heads/managed/pdf
```

agentx deletes the record of where the skill came from and the placements it made, by the same rules as any removal, and takes the skill out of the settings. A copy placement may be the last copy of the skill on your machine: if it differs from the version the skill was installed at, or agentx cannot tell which version that was, agentx still removes it and warns you that your changes went with it, as in `cursor's copy of pdf was different from its base version; removing it deleted those changes`. Copy anything you want to keep out of it first. If a directory without a `SKILL.md` is still in the library under that name, agentx leaves it where it is and says so. `--from <client>` is refused with exit code 6 for such a skill: with nothing in the library, there is no skill for one client to keep. Leave `--from` out.

### Forks

Removing a fork is not this command; it has its own, and `agentx skill remove <fork>` stops with exit code 6, with or without `--from universal`. You can still take a fork's placements away with `--from <client>`. The universal clients keep seeing a fork until the fork itself is removed, so `--from` naming one is refused with a hint that says so rather than offering `--from universal`.

## List your skills

```sh
agentx skill list
```

```text
3 skills
  docx   managed    modified, source removed  https://github.com/me/skills/docx                2 placements
  notes  unmanaged  -                         (none)                                           2 placements
  pdf    managed    current                   https://github.com/anthropics/skills/skills/pdf  4 placements
```

Each row shows the skill, what agentx knows about it, how it stands against the version it was installed at, where it came from and how many placements it has, one per client that sees it.

- `managed`: installed by agentx, with an upstream and a version it can compare against.
- `fork`: a skill of your own in the account repo.
- `unmanaged`: a directory in the library agentx did not install. It is inventoried and otherwise left alone.
- `current` or `modified`: whether the directory still holds the version it was installed at. Every change counts, whatever tool made it: a file you edited, added or deleted, but also a file made executable, a file replaced by a symlink and a symlink added. See what changed with [`agentx skill diff`](#see-what-you-changed).
- `displaced`: a client that should see the skill through a link from its own skills directory has a real directory there instead, which is what an installer that copies over links leaves. For a client you placed a copy in, it is the other way round: a link to the library where the copy should be. Put it back with [`agentx skill repair <name>`](#repair-placements).
- `missing`: an enabled client has nothing of the skill in its own skills directory, because you placed the skill with `--to`, removed it with `--from`, or the placement was deleted. Place it in one client with `agentx skill place <name> --to <client>`, or in every client it is missing from with [`agentx skill repair <name>`](#repair-placements). Universal clients and disabled clients are never missing a skill.
- `source removed`: the source the skill came from is no longer added on this machine. The skill keeps working, stays where it is and keeps its record of where it came from. Add the source again to clear it: see below.

A skill can be in more than one state at once, so the row names each of them: `modified, source removed` is a skill you edited whose source you then removed. `displaced` and `missing` are information only: they never make a command fail.

If a managed skill's directory is deleted from the library outside agentx, the skill has no row, since there is nothing left to compare or place. `skill list` names it in a warning instead, with two ways out:

```text
warning: pdf is managed in the account repo but the library holds no skill directory for it; run 'agentx skill add https://github.com/anthropics/skills --skill pdf' to install it again, or 'agentx skill remove pdf' to stop managing it
```

- Install it again with `agentx skill add`. This works while the source still holds the version you installed. If you fetched the source since and the skill changed upstream, `skill add` refuses and tells you to run `agentx skill remove` first; after that, `skill add` installs the version the source holds now.
- Stop managing it with `agentx skill remove`. This always works: it deletes the skill's record in the account repo and the placements agentx made, and clears the warning.

If the directory is still there but has lost its `SKILL.md`, the warning names it. Move it aside before you install the skill again, since `skill add` does not write over it.

### Bring back a removed source

A managed skill whose source you removed shows `source removed` until you add that source again:

```sh
agentx source add https://github.com/me/skills
```

That clears the state and changes nothing else: the skill, its record and its placements stay exactly as they were. It works with any pin, since a source is identified by its URL. Installing another skill from the source by its URL, or adopting one with [`agentx adopt`](/cli/adopt), adds the source again too.

## See what you changed

Compare a managed skill with the version it was installed at:

```sh
agentx skill diff pdf
```

```text
pdf differs from its base version at 3f2a9c1 in 2 files
diff --git a/SKILL.md b/SKILL.md
index 5d1e2c4..8f0a3b1 100644
--- a/SKILL.md
+++ b/SKILL.md
@@ -3,2 +3,3 @@ name: pdf
 # PDF
 Use this skill to read and fill in PDF forms.
+Always keep the original file.
diff --git a/notes.md b/notes.md
new file mode 100644
index 0000000..2f1c9e0
--- /dev/null
+++ b/notes.md
@@ -0,0 +1 @@
+My own notes.
```

There is one diff per file, and every path is relative to the skill's directory. A file you moved shows as one deleted and one added. A skill that holds exactly its base version prints `pdf matches its base version at 3f2a9c1`. A file that is not UTF-8 text prints as the bytes it holds. Control characters other than the tab, such as the carriage return of a Windows line ending, print as a space, so nothing in a file can control your terminal. Use `--json` to get the patch exactly as git wrote it.

The diff only reads your library: nothing is written to it. agentx compares the files exactly as they are on disk, so no `.gitignore` or other git setting hides a file from the comparison. A repository nested in the skill, or anything else git cannot record, such as a named pipe, is left out with a warning naming it. Such a skill never matches its base version: `skill list` shows it as `modified`, the diff ends with the number of paths git cannot record, as in `pdf differs from its base version at 3f2a9c1 only in 1 path git cannot record`, and `skill revert` refuses it until you move the path out of the skill.

An earlier version of agentx could store a skill from a source that uses an old kind of file mode in a form that makes it show as `modified` even though you changed nothing. `skill diff` then says so instead of showing a diff:

```text
pdf differs from its base version at 3f2a9c1 only in how the account repo stores it; run 'agentx skill revert pdf' to store it as git writes it today, which changes no file
```

Run `agentx skill revert pdf`. It stores the version again without touching your files, and the skill shows as `current`. While the source still holds that version, installing it again with `agentx skill add` does the same.

A skill agentx did not install, and a fork, have no base version to compare with, so `skill diff` stops with exit code 6.

## Revert a skill

Put a managed skill back to the version it was installed at:

```sh
agentx skill revert pdf
```

```text
✓ reverted pdf to its base version at 3f2a9c1, 1 copy placement refreshed
```

Reverting discards every change made to the skill since it was installed: files you added are deleted, and files you changed or deleted come back as they were, with their permissions. Run `agentx skill diff` first to see what you are about to discard.

Only what the skill held when you ran the command is discarded. If the skill changes while the revert runs, for example because your editor saves a file, or another agentx command changes the version it was installed at, agentx stops with exit code 6 and discards nothing. Run `agentx skill diff` to see the change, then revert again. agentx keeps what it replaces until the revert is complete, so an interrupted revert finishes on the next command and loses nothing.

A copy placement is handled on its own:

- A copy that already holds the installed version is left alone.
- A copy that holds the changes you are reverting is reverted too.
- A copy you edited in place is kept exactly as it is and skipped, with the warning for a [copy that differs from the library](#a-copy-that-differs-from-the-library).
- A copy agentx cannot read is kept as it is and skipped, with a warning that says why.

A skill that holds a repository of its own, or anything else git cannot record, is not reverted: the revert would delete it with no record of it anywhere. agentx names what it found; move it out of the skill, then revert again.

If the skill's library directory is a symlink to a directory of your own, `skill revert` stops with exit code 6 and discards nothing: a revert replaces the library directory, so it would remove your link and leave your changes where the link leads. Replace the link with the directory it points to, then revert again, or use `agentx skill diff` to see what differs and put the files back yourself.

A skill agentx did not install, and a fork, have no base version to revert to, so `skill revert` stops with exit code 6. Reverting a skill that already holds its base version changes nothing. If the version was stored in an older form, as described under [See what you changed](#see-what-you-changed), the revert stores it again and changes none of your files:

```text
✓ pdf already matches its base version at 3f2a9c1; nothing was reverted, and its import branch now stores that version as git writes it today
```

## Repair placements

Put back the placements `agentx skill list` shows as `missing` or `displaced`:

```sh
agentx skill repair pdf
```

```text
✓ repaired pdf in 2 configurations
  claude-code  relinked  symlink  ~/.claude/skills/pdf -> ~/.agents/skills/pdf
  cursor       placed    symlink  ~/.cursor/skills/pdf -> ~/.agents/skills/pdf
```

Each row is one client and what agentx did there:

- `placed`: the client had nothing of the skill, so agentx placed it: a copy if you placed a copy there before, a link otherwise.
- `relinked`: the client had a real directory where the link belongs, so agentx replaced it with the link.
- `copied`: the client had a link to the library where you placed a copy, so agentx replaced it with a copy.

Only what `skill list` flags is repaired. A link of your own to another directory, a copy you edited, and clients you disabled are left as they are. So is a client's directory that the library entry itself is a symlink to, for example `~/.agents/skills/pdf` linked to `~/.claude/skills/pdf`: that directory is the library's own content, so `skill list` flags nothing there and `skill repair` never replaces it. To place the skill in one more client, use [`agentx skill place <name> --to <client>`](#place-a-skill-you-already-have) instead.

### When the directory differs from the library

A real directory that holds exactly what the library holds is replaced with the link without asking: nothing is lost. If it holds anything else, for example because you edited the skill there, one of the two versions has to go, so `skill repair` stops with exit code 6 and changes nothing:

```text
error: ~/.claude/skills/pdf is a directory whose content differs from the library's pdf, so nothing was repaired
hint: to keep the library's content and discard it, run 'agentx skill repair pdf --keep-library'; to make its content the library's, run 'agentx skill repair pdf --keep-placement'
```

Choose what survives:

- `--keep-library` keeps the library version. The directory is deleted and replaced with the link.
- `--keep-placement` keeps the directory's version. Its content replaces the library directory, then the directory is replaced with the link, so every client sees your version. The skill shows as `modified` from then on, unless the directory held the version you installed; see what differs with [`agentx skill diff`](#see-what-you-changed), or go back to the installed version with [`agentx skill revert`](#revert-a-skill).

```sh
agentx skill repair pdf --keep-placement
```

```text
✓ repaired pdf in 1 configuration
  claude-code  relinked  symlink  ~/.claude/skills/pdf -> ~/.agents/skills/pdf
  the library now holds what ~/.claude/skills/pdf held
```

Give one of the two, not both. With `--keep-placement`, copy placements follow the new library version as they follow a revert: a copy that held the library version, or the version you installed, is refreshed, and a copy you edited is kept and skipped with a warning.

`--keep-placement` keeps one directory. If two clients hold directories that differ from each other, move aside every one but the directory you want to keep, then repair again. It also stops with exit code 6 if the library entry is a link to a directory of your own, if the directory has no `SKILL.md`, or if it holds a repository of its own or anything else git cannot record.

Only what the directories held when you ran the command is replaced. If a directory or the library changes while the repair runs, agentx stops with exit code 6 and changes nothing; run the repair again. agentx keeps what it replaces until the repair is complete, so an interrupted repair finishes on the next command and loses nothing.

### What cannot be repaired

A skill with no missing or displaced placement is left as it is, and the command says so: `pdf has no missing or displaced placement; nothing was repaired`.

A skill agentx did not install, and a fork, have no drift to repair, so `skill repair` stops with exit code 6. So does a managed skill whose library directory is gone: install it again with `agentx skill add`, or stop managing it with `agentx skill remove`, as the error says.

A client's directory that holds the directory a library entry links to is never replaced, whatever flag you give, because replacing it would delete that skill's content. For example, if `~/.agents/skills/pdf` is a link to `~/.claude/skills/pdf/src`, `skill repair` stops with exit code 6. Replace the link with the directory it points to, moving that directory out of the client's directory, then repair again.

## Script it

Add `--json` to get one `library_skill` event per skill:

```sh
agentx --json skill list
```

```json
{"type":"library_skill","schema_version":1,"name":"pdf","kind":"managed","source":"https://github.com/anthropics/skills","subpath":"skills/pdf","upstream_commit":"3f2a9c1e...","base_hash":"9a8b7c6d...","content_hash":"9a8b7c6d...","state":"current","placements":[{"configuration":"claude-code","path":"/home/me/.claude/skills/pdf","mode":"symlink","kind":"symlink"},{"configuration":"codex","path":"/home/me/.agents/skills/pdf","mode":"library","kind":"library"},{"configuration":"cursor","path":"/home/me/.claude/skills/pdf","mode":"symlink","kind":"symlink"},{"configuration":"cursor","path":"/home/me/.cursor/skills/pdf","mode":"symlink","kind":"symlink"},{"configuration":"gemini-cli","path":"/home/me/.agents/skills/pdf","mode":"library","kind":"library"}],"universal":["codex","gemini-cli"]}
{"type":"result","schema_version":1,"ok":true}
```

`placements` lists every path each client sees the skill through, so Cursor, which also reads Claude Code's skills directory, appears twice. The text of `skill list` counts Cursor once, and that of `skill add` and `skill place` shows one row per client.

`skill place` and `skill remove --from <client>` emit one `library_skill` event too, whose placements are what the rescan found in the clients the command named; `skill remove` without `--from`, or with `--from universal`, emits none, the skill being gone. `skill add` emits a `source` event for the source it installed from, whose `last_fetched` says when it was fetched, then a `progress` event per step per skill (`blobs`, `import` and `install`), then one for the `rescan` at the end, then one `library_skill` event per skill it installed, then `result` with a one-line summary. `total` counts the steps the run planned; a skill it has to skip takes its remaining steps out of that count, so the run always ends on its total.

`universal` lists every universal client on this machine, whether or not the command placed into it, and is `[]` when none is installed. `skill add` and `skill place` end their `result` summary with the same `always available to universal clients:` words as their text.

The event carries two content hashes, and each name means one thing everywhere agentx uses it: `base_hash` is the version the skill was installed at, and `content_hash` is what the library directory holds now. `state` compares the files themselves, their permissions and symlinks included, so a skill whose only change is a file made executable is `modified` while its two hashes still agree.

`drift` lists every other way a managed skill has drifted, beside its `state`, and is absent when there is none. Its values are `displaced`, `missing` and `source removed`:

```json
{"type":"library_skill","schema_version":1,"name":"docx","kind":"managed","source":"https://github.com/me/skills","subpath":"docx","upstream_commit":"8b1e0f4a...","base_hash":"5e4d3c2b...","content_hash":"0f9e8d7c...","state":"modified","drift":["source removed"],"placements":[...],"universal":["codex","gemini-cli"]}
```

Read `drift` as a list: more values will join it, and a skill can be in several at once. The snapshot of [`agentx scan`](/cli/scan) and [`agentx serve`](/cli/serve) lists every library skill the same way, under `library`, and `agentx serve` tells you when a skill's state changes, see [Drift](/cli/serve#drift).

`skill diff` emits one `diff` event per file, sorted by path, with the file's `path` relative to the skill's directory, its `status` (`added`, `modified` or `deleted`) and the `patch` git wrote for it:

```json
{"type":"diff","schema_version":1,"name":"pdf","path":"notes.md","status":"added","patch":"diff --git a/notes.md b/notes.md\nnew file mode 100644\n..."}
```

`path` and `patch` are JSON strings, which hold UTF-8 only: a byte that is not valid UTF-8, in a file name or in a file that is not UTF-8 text, arrives as `U+FFFD`. Such a patch is for display; the text output prints the bytes as they are.

`skill revert` and `skill repair` emit one `library_skill` event for the skill, with every placement, as `skill list` does. The `result` summary of `skill repair` counts the clients it repaired, as in `repaired pdf in 2 configurations`, and ends with `; the library now holds what <path> held` after `--keep-placement` or `; discarded what <path> held` after `--keep-library`.

## Where it is recorded

Every install writes one commit per skill in the account repo in agentx home: the version's files, the source it came from, the last upstream commit that changed the skill and its content hash. That commit is the same on every machine that installs the same version, however recently each one fetched the source, so your machines agree on what "the version you have" means without sending anything anywhere. A skill installed on its own and the same skill installed as part of a bulk install get the same commit.

## Exit codes

- `1`: the command line names no skill to install, the flags contradict each other (`--all` with `--skill`, `--except` without `--all`, `--except` leaving nothing, or `--from universal` with a client that is not universal), it names the source with another branch or tag than its pin, `skill add` is given something that is not a source (for example, the name of a skill the library already holds), `skill place` was given no `--to`, or `skill repair` was given both `--keep-library` and `--keep-placement`.
- `3`: the source, or the files of the skill, could not be fetched.
- `5`: a source id names no source on this machine (for a source you removed, the hint names the `agentx source add` command that brings it back), the source did not serve a skill's files, the path or a skill named by `--skill` or `--except` does not exist in the source, or `--to` or `--from` names a configuration that is not detected. For `skill place`, `skill diff`, `skill revert` and `skill repair`, also a name the library does not hold as a skill; for `skill remove`, a name that is neither a skill of the library nor a managed skill whose library directory is gone.
- `6`: the library already holds a different skill under that name, the name is already managed at another version, the skill's name cannot be both a directory and a git branch, the skill's directory in the source is not one agentx can record, the skill holds a file whose path would put it outside the skill's directory, agentx cannot use your library directory, or an interrupted change has to be resolved before anything else can run. The message names what to restore; if you would rather keep what is there, move the named file in `~/.agentx/mutations` aside. For `skill remove`, it is also `--from` naming a universal client, one that reads the library directly, even next to `--from universal`, removing a name that is a fork, and `--from <client>` for a skill whose library directory is gone. For `skill diff` and `skill revert`, it is a skill agentx did not install or a fork, which have no base version, or a managed skill whose import branch records no version agentx can read; for `skill diff`, also a file that changed while agentx read it; for `skill revert`, also a skill that changed while it was being reverted, a skill whose installed version another command changed meanwhile, a skill that holds something git cannot record, or a skill whose library directory is a symlink. For `skill repair`, it is a skill agentx did not install, a fork, a managed skill whose library directory is gone or whose import branch records no version agentx can read, a displaced directory that differs from the library when neither `--keep-library` nor `--keep-placement` is given, a skill or placement that changed while it was being repaired, a displaced directory that holds the directory a library entry links to, and, for `--keep-placement`, directories that differ from each other, a library directory that is a symlink, or a directory with no `SKILL.md` or holding something git cannot record. In a run of several skills, `6` is also the code when the skills that were skipped disagree about why: a run whose failures all have one cause exits with that cause, so a batch that skipped two skills the source did not serve exits `5`.
- `7`: another agentx command is running. Retry when it finishes.
- `8`: the account repo in agentx home cannot be read or written. Run `agentx doctor`.
- `10`: agentx could not read its own settings file, the library still held the skill after `skill remove` took it away, or agentx hit an error it has no better answer for. Run `agentx doctor`.
