---
title: "agentx machine"
description: "See the machine's stable id and label and where agentx keeps its files, rename the machine, or reset the id."
---

agentx gives each computer a machine id and a label. The id identifies the machine in scans, snapshots and the commits agentx writes. It stays the same when you reinstall agentx. The label is a readable name that you can change. The same command shows where agentx keeps its files on this machine.

## Show the machine

```sh
agentx machine
```

```text
Machine id    3ea501b8fb5db1ad3cc85268972d7012
Label         my-laptop
Derivation    platform
Home          /home/me/.agentx
Settings      /home/me/.agentx/settings.json
Library       /home/me/.agents/skills
Account repo  /home/me/.agentx/account.git (2.3 MiB)
```

`Derivation` tells you where the id comes from:

| Value | What it means |
|---|---|
| `platform` | agentx computes the id from the computer's platform id and your user id. The platform id is `/etc/machine-id` on Linux and the hardware UUID on macOS. Reinstalling agentx on the same computer gives the same id. |
| `random` | agentx generated the id and stores it in `machine.json` in agentx home (`~/.agentx` by default). This happens when the computer has no platform id, or after you [reset the id](#reset-the-id). |

## See where agentx keeps its files

The last four rows say where agentx keeps its files on this machine:

| Row | What it is |
|---|---|
| `Home` | [agentx home](/#key-terms), `~/.agentx` unless `AGENTX_HOME` says otherwise. Everything agentx keeps on this machine lives here. |
| `Settings` | the [machine settings](/cli/config) file, `settings.json` in agentx home. |
| `Library` | the [library](/#key-terms), `~/.agents/skills` unless `AGENTX_LIBRARY` says otherwise, where agentx installs skills. |
| `Account repo` | the [account repo](/#key-terms), `account.git` in agentx home, and its size on disk. It shows `not created yet` until the first command that needs it, such as `agentx source add` or `agentx skill new`, creates it. |

The size counts the files in `account.git` alone. The worktrees of your own skills, under `worktrees` in agentx home, are not part of it. There is no cache to clear: what agentx fetched from your sources lives in the account repo.

With `--json`, the `machine` event carries the same as `home`, `settings_file`, `library`, `account_repo` and `account_repo_bytes`. The last two are absent until the account repo exists. See [Environment variables](/cli/output#environment-variables) for `AGENTX_HOME` and `AGENTX_LIBRARY`.

## Rename the machine

```sh
agentx machine rename "work laptop"
```

```text
✓ machine label is now work laptop
```

Until you set a label, agentx uses the hostname. You can also set the label with [`agentx config set label`](/cli/config#set-a-setting). The label must be one line of at most 256 bytes, with visible text and no control characters. agentx rejects any other label with exit code 1.

## Reset the id

```sh
agentx machine reset-id
```

```text
✓ machine id is now 7c1f0a2e9b3d4c5e8f6a1b2c3d4e5f60
```

Reset the id when two computers show the same id, for example after you clone a virtual machine. The new id is random. agentx keeps using it until you delete `machine.json` in agentx home. agentx then computes the id from the platform id again, or generates a new random id if the computer has no platform id.

If another agentx command is running, `rename` and `reset-id` stop with [exit code 7](/cli/output#exit-codes). Run them again when that command finishes.
