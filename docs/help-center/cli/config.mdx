---
title: "agentx config"
description: "List, get and set the settings of one machine."
---

Machine settings live in `settings.json` in agentx home, `~/.agentx` by default. agentx does not sync them. To copy them to another machine, use [`agentx export`](/cli/export).

This page uses the terms configuration, library and placement. See [Key terms](/#key-terms).

## List every setting

```sh
agentx config list
```

```text
schema_version           1
label                    my-laptop
accept_operations        false
ignore_system_files      true
disabled_configurations  (none)
sources                  []
copy_mode                {}
```

An empty `disabled_configurations` shows as `(none)`. `sources` and `copy_mode` print as one line of JSON.

| Key | Meaning |
|---|---|
| `schema_version` | The settings file format version. |
| `label` | The name of this machine. It is the hostname until you set it. [`agentx machine rename`](/cli/machine) also sets it. |
| `accept_operations` | Reserved for a later version. agentx does not use it yet. |
| `ignore_system_files` | Whether agentx ignores files your operating system or editor leaves in a skill, such as `.DS_Store`, `Thumbs.db`, `*.swp` and `*~` backups. On by default. See [Files that do not count](/cli/skill#files-that-do-not-count) and [Files that stay local](/cli/fork#files-that-stay-local). |
| `disabled_configurations` | The configurations agentx skips when you install or place a skill without `--to`. See [Enable or disable a configuration](#enable-or-disable-a-configuration). |
| `sources` | The sources skills are installed from, managed with [`agentx source`](/cli/source). |
| `copy_mode` | For each skill placed as a copy, the configurations that hold the copy. Written by `agentx skill add --copy` and `agentx skill place --copy`, and cleared by `agentx skill remove`. |

## Get one setting

```sh
agentx config get label
```

The command prints the bare value, so a script can use it directly. For an unknown key, agentx exits with code 1 and lists the keys.

## Set a setting

```sh
agentx config set label "work laptop"
agentx config set ignore_system_files false
```

```text
✓ label is now work laptop
```

You can set `label`, `accept_operations` and `ignore_system_files`:

- `accept_operations` and `ignore_system_files` take `true` or `false`.
- A label is one non-empty line of at most 256 bytes with no control character in it.

agentx exits with code 1 for an invalid value, an unknown key, or a key you cannot set. For a key, the error lists the keys you can set.

If another agentx command is running, the command stops with exit code 7. Run it again when the other command finishes.

## Enable or disable a configuration

```sh
agentx config disable windsurf
agentx config enable windsurf
```

```text
✓ windsurf is now disabled
✓ windsurf is now enabled
```

Every configuration `agentx scan` detects starts enabled. When you install or place a skill without `--to`, agentx places it only in enabled configurations. Disable a configuration to skip it. Enable it to include it again.

Use the id that `agentx scan` shows in parentheses. For an id that scan does not detect, agentx exits with code 5 and lists the detected ids.

A client that reads the library directly, such as Codex, still sees every skill when you disable it. See [Clients that see every skill](/cli/skill#clients-that-see-every-skill).

### Place the skills you already have

Enabling a client changes only where later installs go. To also place every skill in your library in that client, add `--place-all`:

```sh
agentx config enable cursor --place-all
```

```text
✓ cursor is now enabled
✓ placed 2 skills in cursor
  pdf   symlink  /home/me/.cursor/skills/pdf -> /home/me/.agents/skills/pdf
  xlsx  symlink  /home/me/.cursor/skills/xlsx -> /home/me/.agents/skills/xlsx
```

The output has one row for each skill, with its path in Cursor's skills directory.

agentx places each skill as a symlink. If agentx already keeps a copy of a skill for this client, it places a copy. See [Copy instead of link](/cli/skill#copy-instead-of-link).

If the run stops part way, the next agentx command finishes it.

A client that reads the library directly, such as Codex, already sees every skill. See [Clients that see every skill](/cli/skill#clients-that-see-every-skill). For such a client, `--place-all` places nothing and lists what the client sees:

```text
✓ codex is now enabled
✓ codex reads the library and already sees 2 skills; nothing was placed
  pdf   library  /home/me/.agents/skills/pdf
  xlsx  library  /home/me/.agents/skills/xlsx
```

To place one skill at a time, use [`agentx skill place`](/cli/skill#place-a-skill-you-already-have).

### When a placement is skipped

agentx skips a placement when something of yours is already at the path, or when it cannot write to the client's skills directory. It prints a warning for each skipped path, places the other skills, and exits with code 0. The client is then enabled with only some of your skills:

```text
warning: /home/me/.cursor/skills/pdf is not this skill and was left as it is; no placement was made for cursor
✓ cursor is now enabled
✓ placed 1 skill in cursor, 1 placement skipped
  xlsx  symlink  /home/me/.cursor/skills/xlsx -> /home/me/.agents/skills/xlsx
```

Cursor does not see pdf, so pdf has no row. If Cursor sees pdf through another client's directory, such as Claude Code's, the row shows that path.

agentx also skips a copy it keeps for the client when the copy differs from the library, for example because you edited it. The copy stays as it is. The warning names the commands that replace it:

```text
warning: cursor's copy of pdf is different from the library, so it was left unchanged (/home/me/.cursor/skills/pdf)
  to replace it with the library version: agentx skill remove pdf --from cursor && agentx skill place pdf --to cursor --copy
✓ cursor is now enabled
✓ placed 1 skill in cursor, 1 placement skipped
  xlsx  symlink  /home/me/.cursor/skills/xlsx -> /home/me/.agents/skills/xlsx
```

See [A copy that differs from the library](/cli/skill#a-copy-that-differs-from-the-library).

## Fix a broken file

If agentx cannot parse `settings.json`, every command that reads it exits with code 10 and names the file. Fix the JSON, or delete the file to start again from defaults.

If a later version of agentx wrote `settings.json`, every command that reads it exits with code 10 and says which schema version the file has. Upgrade agentx to that version. Keep the file: it holds sources and settings the later version needs. `agentx doctor` shows the same error in its `settings` row.

## Exit codes

For what each code means, see [Exit codes](/cli/output#exit-codes). These causes are special to `agentx config`:

- `1`: an invalid value, an unknown key, or a key you cannot set.
- `5`: `config enable` or `config disable` names a configuration `agentx scan` does not detect.
- `7`: another agentx command is running. `set`, `enable` and `disable` stop at once.
- `10`: agentx cannot parse `settings.json`, or a later version of agentx wrote it. See [Fix a broken file](#fix-a-broken-file).
