---
title: "agentx scan"
description: "See every agent configuration with the skills, MCP servers and plugins each one has."
---

`agentx scan` reads your agent clients' directories, their MCP configuration files and your skill library (`~/.agents/skills`), then prints what it finds. It changes none of these files. It starts MCP servers only when you ask for a [handshake](#handshake-the-servers).

A configuration is detected when its configuration directory exists, such as `~/.claude` for Claude Code or `~/.cursor` for Cursor. If agentx detects none, it prints `No agent configurations detected.`

## Scan the machine

```sh
agentx scan
```

```text
3 configurations, 4 skills, 2 servers, 4 plugins detected

Claude Code (claude-code)  /home/me/.claude  enabled  3 skills, 1 plugin
  skills:
    commit  symlink    user  /home/me/.claude/skills/commit -> /home/me/.agents/skills/commit
    format  directory  user  /home/me/.claude/plugins/cache/acme-tools/formatter/1.2.0/skills/format  (plugin formatter)
    review  directory  user  /home/me/.claude/skills/review
  plugins:
    formatter  1.2.0  1 skill

Codex (codex)  /home/me/.codex  enabled  2 skills, 2 plugins
  skills:
    commit  directory  user  /home/me/.agents/skills/commit
    sales   directory  user  /home/me/.codex/plugins/cache/acme-tools/sales/1.0.8/skills/sales  (plugin sales)
  plugins:
    notes  local  (disabled)
    sales  1.0.8  1 skill

Cursor (cursor)  /home/me/.cursor  enabled  2 skills, 2 servers, 1 plugin
  skills:
    commit  symlink    user  /home/me/.claude/skills/commit -> /home/me/.agents/skills/commit
    review  directory  user  /home/me/.claude/skills/review
  servers:
    context7  stdio            npx -y @upstash/context7-mcp
    stripe    streamable-http  https://mcp.stripe.com
  plugins:
    thermos  9f86d081884c7d659a2feaa0c55ad015a3bf4f1b
```

How to read it:

- The first line counts the whole machine. A skill with the same content in several configurations counts once, and so does a server declared in several. A plugin counts once for each configuration it is installed in.
- Each agent configuration then gets a section. Its first line shows the client name, its id, its configuration directory, `enabled` or `disabled`, and how many skills, servers and plugins it has. An enabled configuration gets new skills by default; see [Enable or disable a configuration](/cli/config#enable-or-disable-a-configuration).
- `skills:` lists every skill the configuration can see, one per line: the skill name, its [kind](#read-the-kind), its scope (`user`, or `project` with [`--project`](#include-a-project)) and the path the client reads. A skill from a plugin ends with `(plugin <name>)`.
- `servers:` appears when the configuration declares MCP servers, one per line: the name, the transport (`stdio`, `sse` or `streamable-http`) and the command line or URL. A server from a plugin ends with `(plugin <name>)`, and a server turned off in its client shows `(disabled)`. After a [handshake](#handshake-the-servers), the row also shows a count or why the handshake failed.
- `plugins:` appears when the configuration has plugins, one per line: the name, the version, how many skills and servers the plugin provides here, and `(disabled)` when the client has turned it off.

agentx cleans text from files it did not write before it prints it. See [Text output](/cli/output#text-output).

## Read the kind

| Kind | Meaning |
|---|---|
| `symlink` | The path is a symlink. The arrow shows where it points. |
| `copy` | The path is a real directory that agentx keeps as a copy of a library skill for this configuration. |
| `directory` | The path is a real directory. |

## See who reads what

A client can read other clients' directories. Cursor reads `~/.claude/skills` and `~/.codex/skills` next to its own `~/.cursor/skills`, so a skill you put in the Claude Code directory appears under Cursor too. Some clients, such as Codex and Gemini CLI, read the library at `~/.agents/skills` directly, so every library skill appears under them without any link in their own directories.

## Read the servers

agentx reads the user-scope MCP configuration of Claude Code (`~/.claude.json`), Codex (`~/.codex/config.toml`), Cursor (`~/.cursor/mcp.json`), Gemini CLI (`~/.gemini/settings.json`), Windsurf (`~/.codeium/windsurf/mcp_config.json`) and GitHub Copilot (`~/.copilot/mcp-config.json`). Other clients contribute skills only.

The inventory shows the command and arguments of a local server and the URL of a remote one. It hides the values of environment variables and headers. A secret written directly into a command argument or a URL still appears.

agentx counts a server declared in several clients as one server. It recognises a remote server by its URL, and a local `npx`, `uvx`, `pipx` or `docker` server by its package or image, whatever the version. It recognises any other local server by its exact command line on this machine.

## Handshake the servers

```sh
agentx scan --handshake
```

```text
  servers:
    context7  stdio            npx -y @upstash/context7-mcp  12 tools
    stripe    streamable-http  https://mcp.stripe.com        9 tools
```

A handshake starts or connects to every MCP server and records the tools, prompts and resources it offers. The count on the row includes all of them. Each server gets ten seconds. agentx runs each server the way the client that declares it does:

- agentx fills in placeholders such as `${API_KEY}` from your environment, the way the declaring client does. The inventory shows the declaration as written.
- For a remote server that Claude Code declares, agentx leaves Claude Code's credential variables empty in the URL and headers, as Claude Code does. These include `AWS_SECRET_ACCESS_KEY` and every `ANTHROPIC_*` and `CLAUDE_*` variable. Run with `--verbose` to see which ones agentx left empty.
- A remote server receives its declared headers at its declared URL. For Codex, agentx reads the values of `env_http_headers` and `bearer_token_env_var` from your environment.
- agentx skips a server you turned off in its client, and its row shows `(disabled)`. agentx reads this setting from Codex (`enabled = false`), Gemini CLI (`mcp.excluded`, `mcp.allowed` and `gemini mcp disable`) and GitHub Copilot (`/mcp disable`). Claude Code, Cursor and Windsurf store it where agentx cannot read it, so agentx handshakes those servers.

agentx compares what each server offers. Two servers with the same command or URL but different tools count as two servers. The same server declared in two clients with the same tools stays one server.

agentx keeps the results in `handshakes.json` in [agentx home](/#key-terms), `~/.agentx` by default. A later scan without `--handshake` shows them until the next handshake replaces them.

### Fix a failed handshake

When a handshake fails, the server's row says why, a warning names its file, and a hint says what to do. The server keeps the results of its last successful handshake, if any, and the scan still succeeds.

```text
  servers:
    notion   streamable-http  https://mcp.notion.com/mcp  needs sign-in
    browser  streamable-http  http://127.0.0.1:9010/mcp   unreachable
```

| Row says | What to do |
|---|---|
| `needs sign-in` | The server answered 401 or 403. agentx sends only the declared headers and cannot use your client's browser sign-in. Declare a header with an API key, or renew the key if one is declared. For Codex's `bearer_token_env_var`, set that variable in the shell you run agentx from. |
| `unreachable` | Start the server, or check the URL and your proxy settings. |
| `command not found` | Check the command in the declaration. A bare name is looked up on your `PATH`. A relative path resolves against the declared `cwd`, else against the directory you run agentx in. |
| `timed out` | Give each server more time, for example `AGENTX_HANDSHAKE_TIMEOUT=30s agentx scan --handshake`. |
| `handshake failed` | The server exited or answered badly. Run its command or request its URL by hand. |

## Read the plugins

Plugins are listed under the configuration they are installed in, with their version. The skills and MCP servers a plugin provides appear in the configuration's list like any other, marked with the plugin's name. A skill installed both on its own and through a plugin, with the same content, counts as one skill and appears on two rows.

| Client | What agentx reads |
|---|---|
| Claude Code | The install records in `~/.claude/plugins/installed_plugins.json` and each plugin's directory. |
| Codex | The `[plugins."<name>@<marketplace>"]` tables in `~/.codex/config.toml` and the plugin copies under `~/.codex/plugins/cache`. A plugin, or a plugin's server, with `enabled = false` shows `(disabled)`. A plugin installed through your account has no table, so it shows no enabled state. |
| Cursor | Your local plugins under `~/.cursor/plugins/local` and the marketplace plugins cached under `~/.cursor/plugins/cache`. Cursor stores which plugins are enabled in your account, so a listed plugin may be turned off. Claude Code plugins that Cursor also loads are listed under Claude Code only. |
| Gemini CLI | The extensions under `~/.gemini/extensions`. |

A plugin's version is what its manifest or install record says. Without one, a Codex plugin or a Cursor marketplace plugin shows its cache directory name, such as `local` or a commit id.

## Include a project

```sh
agentx scan --project ~/code/my-app
```

Adds the skills in the project's own skills directories, such as `.claude/skills`, `.cursor/skills` and `.agents/skills`. Their scope is `project`. agentx only reads the project. Without the flag, agentx scans only your user directories, scope `user`.

## Rescan after a change

```sh
agentx scan --configuration cursor
```

`--configuration` names the configuration that changed. agentx checks that the id is detected, then scans the whole machine as usual. An id that is not detected exits with code 5 and lists the detected ids.

## Warnings

These problems do not stop the scan. agentx prints each one on stderr as `warning: ...` after the inventory:

- An MCP configuration file that cannot be parsed.
- A server whose handshake failed. See [Fix a failed handshake](#fix-a-failed-handshake).
- A plugin manifest that cannot be read. The warning names the file.
- A Cursor plugin copy that Cursor did not finish writing: agentx does not list it. A Cursor plugin manifest path that leads outside the plugin: agentx skips that path.
- A broken symlink in a skills directory: agentx skips it.
- A `SKILL.md` whose frontmatter is not valid YAML or has no name: agentx names the skill after its directory.
- A symlink inside a skill that points outside the skill: agentx skips that file.

Several broken symlinks in one skills directory make one warning that names the directory and lists the links:

```text
warning: /home/me/.qwen/skills: 3 broken symlinks (audit, polish, shape), skipped
```

Delete the listed links to clear the warning.
