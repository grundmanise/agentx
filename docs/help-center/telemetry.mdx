---
title: "Usage data"
description: "What anonymous usage data agentx can send, and how to turn it on or off."
---

agentx can send anonymous usage data, so its maintainers learn which commands fail and on which platforms. It sends nothing until you agree.

## Answer the question

The first time you run [`agentx scan`](/cli/scan) in a terminal, agentx prints the inventory, then what it would send, and asks:

```text
Send anonymous usage data? [y/N]
```

Type `y` to agree. Press Enter, or type anything else, to decline. agentx stores your answer in the `telemetry` setting and does not ask again.

A scan without a terminal, such as one in a script or with `--json`, does not ask. The next scan in a terminal asks instead.

In the desktop app, a dialog asks the same question after the first scan.

## What is sent

agentx sends one event for each command you run, when the command ends. [`agentx serve`](/cli/serve) also sends one when it starts.

| Field | Value |
|---|---|
| `telemetry_id` | An id derived from the machine id |
| `cli_version` | The version [`agentx version`](/cli/version) prints |
| `schema_version` | The version of the `--json` output |
| `os`, `arch` | `darwin` or `linux`, `amd64` or `arm64` |
| `command` | The command words only, such as `skill add` or `config set`, without arguments or flag values |
| `exit_code` | The [exit code](/cli/output#exit-codes); absent on the `serve` start event |
| `duration_ms` | How long the command ran |
| `json` | Whether you gave `--json` |
| `at` | When the command ended, to the minute |

agentx sends nothing else: no path, skill name, server name, source URL, configuration id, hostname, machine label, error message or environment variable.

agentx derives the telemetry id from the machine id with a one-way hash. Nobody can get the machine id back from it. [`agentx machine reset-id`](/cli/machine) changes both.

The same answer covers crash reports. When agentx crashes, it sends the error type, the error message and a stack trace, with every path removed.

## What the desktop app sends

The same answer covers the desktop app. Each time it opens, it sends one event under the same telemetry id:

| Field | Value |
|---|---|
| `app_version` | The version of the app |
| `cli_version` | The version of agentx inside the app |
| `os`, `arch` | `darwin` or `linux`, `amd64` or `arm64` |

When the app crashes, it sends the error type, the error message and a stack trace, with every path removed. It sends nothing about its window or your device: no page address, user agent, screen size, time zone or language, and it stores nothing for the data on your machine.

## Change your answer

```sh
agentx config set telemetry off
agentx config set telemetry on
```

`agentx config get telemetry` prints `on`, `off` or `unset`. When you turn it off, agentx deletes the events it has not sent yet.

In the desktop app, use the **Send usage data** switch in Settings. The app stops sending as soon as you turn it off.

## Turn it off for every run

Set `DO_NOT_TRACK=1` in your environment. agentx then neither asks nor sends, whatever the setting says.

A build from source, of agentx or of the desktop app, has no destination for the data, so it never asks and never sends.

## Where the data goes

agentx sends the events to a hosted analytics service in the EU region. It keeps each event in `telemetry/` in agentx home until it is sent: at most 500 events, each for at most seven days. It sends them in the background, so a command never waits for the network.

To send the events somewhere else, such as a collector of your own, set `AGENTX_TELEMETRY_ENDPOINT` to its address. agentx then posts each batch to `<address>/batch/`.
