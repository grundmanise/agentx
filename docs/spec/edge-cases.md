# Edge cases agentx does not handle specially

agentx is built for realistic skills: folders of Markdown and text files, maybe scripts, images and small subfolders. The cases below get no handling of their own: agentx leaves them to git's own behaviour or fails with a generic error, and loses nothing.

- A skill file with lines of its own that look like conflict markers (`<<<<<<<`, `=======`, `>>>>>>>`): a conflicting `skill update` leaves git's markers at git's default size in the pending merge's worktree, so such a line and a marker look alike there. agentx never reads the markers.
- A file that conflicts for a reason other than its lines, such as a binary file, a file executable on one side only, a symlink meeting a file or a file moved to two places: `skill update` lists it with the words `git status` uses for the versions it has, `both modified` or `added by us` say, and nothing more. `git status` in the worktree says the rest.
- A tracked file or folder of a managed skill whose permissions were changed, a file made `0600` say: `skill update` lays the new version out with `0644`, or `0755` for an executable file and for a folder, less the umask, as `skill revert` does. Files git ignores keep their mode.
- A clean merge that holds two paths differing only in case, a `readme.md` you added and a `README.md` the update adds, on a file system that ignores case, as macOS and Windows do by default: `skill update` fails with the library error, exit code 6, and changes nothing. Rename the file, then update again.
- An import branch an earlier agentx stored in an older form, under a library directory that holds exactly that version: `skill update` merges it as it merges an edited skill. The files it lays out are the same, and the result says `merged its edits cleanly`.
- A new version that cannot be written to disk, a file name longer than the file system allows say, in `skill update --all`: the whole run fails with the library error before a journal is written, and no skill is updated.
